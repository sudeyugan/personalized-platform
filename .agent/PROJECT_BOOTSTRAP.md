# Project Bootstrap Protocol

## 1. 与用户对齐

开始时先发送：

```text
我目前理解的目标：<结果>
我准备先确认：<项目现状、约束、验收方式>
当前需要你确认：<只列影响方向的重要问题；没有则写无>
```

目标、范围或成功标准存在重大歧义时，先做只读调查并提供选项，不直接开始大规模实现。

## 2. 识别项目

检查：

- 新项目、已有项目或一次性原型。
- 技术栈、运行环境、包管理器和关键入口。
- README、贡献指南、现有 `AGENTS.md` 和目录级规则。
- 未提交修改；不得覆盖或清理用户改动。
- 测试、lint、类型检查、构建和 CI。
- 现有超长文件、职责混杂模块和缺少清晰入口的功能目录。
- 外部 API、数据库、部署和敏感数据边界。

只读取与当前目标有关的内容，不通读整个仓库。

## 3. 建立项目地图

填写：

```text
目标：
技术栈：
运行命令：
测试 / 类型检查 / lint / 构建命令：
主要入口：
相关目录：
不可破坏的接口或行为：
风险与未知项：
验收方式：
```

## 4. 初始化开发系统

- 与用户确认并填写 `PROJECT_BRIEF.md`。
- 在 `PROJECT_STATE.md` 建立第一个检查点。
- 将阶段和里程碑写入 `ROADMAP.md`。
- 按项目事实填写 `QUALITY_GATES.md`，不要照抄不存在的命令。
- 根据语言和框架校准 `CODE_STRUCTURE.md` 的文件阈值和例外类型。
- 识别初始风险并写入 `RISKS.md`。
- 已有项目的重要历史决策可按需补入 `DECISIONS.md`，不做无依据推测。
- 执行 `SYSTEM_AUDIT.md` 中的首次审查，记录下一次触发条件。

## 5. 评估扩展能力

按需使用，不盲目安装：

- Web UI：浏览器验证或 Playwright。
- 外部事实：GitHub、Figma、Sentry、Notion、Linear、数据库或部署连接器。
- 重复流程：已有 Skill，或将稳定流程沉淀为 Skill。
- 独立且边界明确的工作：子 Agent；避免同时编辑相同文件。

## 6. 启动报告

```text
项目与技术栈：
目标与范围：
已有规范和验证工具：
准备补充的最小能力：
验收方式：
风险和假设：
待用户确认：
下一步：
```

目标和关键验收未对齐时等待确认；低风险且可逆的技术细节可说明假设后继续。
