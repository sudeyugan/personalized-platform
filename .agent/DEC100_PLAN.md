# DEC-100 已填登录表单的受控接续

2026-10-16用户指出不能假设会话持久，要求授权后自动点击已填表单一次并核验，另询问浏览能力深化。此次只实现认证接续，其他能力仅建议，不视为授权开发。

1. 复用cachedLoginSites逐站明确许可，设置/主窗原生配置/执行器三层绑定，模型参数与网页内容不能授权；旧Edge兼容保持。
2. 固定DOM检查原生已填布尔状态、唯一账号/密码/登录按钮、同源HTTPS POST与当前文档/遮挡；不取value、存储、密码库、Cookie或任意模型选择器。
3. Playwright可信点击一次，每个自有后台上下文/站点保守限一次（结果不明也计入），重新观察和既有业务证据核验；DOM离开登录不是业务成功。

实现中实证发现Playwright普通route跳过HTTP重定向后续请求。补内部仅响应阶段CDP守卫，在后台开页及登录提交前验证3xx Location的同源文档/公网HTTPS范围，防止307/308转发表单到其他网站；不读响应正文、Cookie或密码，不把任意CDP开放给模型。真实临时HTTPS夹具验证同源302、跨站307，避免route.fulfill掩盖网络边界。
4. 未填/验证码/多账号/跨站/不支持或结果未确认暂停，凭据不会交DeepSeek。后台不自动弹窗、不填写密码，不承诺密码管理器headless自动填充。
5. 定向DOM隐私/配置/回执/真实虚构Edge可信POST0→1和pending不重试；冻结后一次分段完整验证（WSL前端/静态＋Windows Rust，避免上轮Windows worker失联），Windows候选运行保护、main正常推送。

本轮不扩大跨域SSO自动权限、密码存取、验证码绕过、任意写入、后台长期监控或下载。校园/企业/真实账号兼容须自然回验；浏览能力深化建议单独讨论。

后续讨论候选（未实现、未获得本轮授权）：优先独立认证链许可（邮箱→SSO→邮箱，不授予SSO正文读取）；其次把现有Edge语义示范/方法接入专用执行器并现场重定位；再做有页数/时间预算的分页聚合与覆盖完整性，最后受限临时下载/文件阅读与确认后写入程序。不是增加任意脚本或凭据工具。

调研参考：Playwright官方认证示例要求等最终跳转/账号页面标志，不能只凭点击或存储状态判断完成（https://playwright.dev/docs/auth）；可信动作的可见/稳定/可接收事件检查见https://playwright.dev/docs/actionability。内部重定向守卫仅采用DevTools Fetch响应阶段Location检查（https://chromedevtools.github.io/devtools-protocol/tot/Fetch/），不向模型暴露该接口。
