# DEC-086：浏览器任务目标与已绑定网站修复

用户反馈：“意图识别不对”“查看一下我的邮箱里有新邮件吗”被反复拒绝；B站关注UP最近更新却返回开播名单。用户明确要求修改，并指出通用能力不足。

根因：学习的关注直播别名过宽，模型选错工具未按当前目标拦截；网站目标依赖有限域名子串，空目标/多邮箱未本地澄清，目标也未显式传给模型。旧通用展示只处理排版，不能保证任务匹配。

实施：独立任务目标/网站解析与有界只读查询流程；目的与工具双重绑定，动态更新不得使用关注直播；已绑定唯一邮箱可自动选用，多邮箱或未知目标明确询问，不遍历其他站点。目标元数据进入本次提示；授权标签页→本次ID→可见正文，单标签自动衔接、歧义/无页面停止提示。方法复用和新学习均检查用途，不以旧流程替代新目标。成功的连接/标签页准备回执不抢占最终答复。

边界：沿用现有Edge扩展/原生只读协议、双侧精确授权、取消/epoch/强制隐私外发复核，不读取Cookie/密码、开启网站授权、增加网页写入/点击/认证接口/后台监控或保存邮件正文。兼容当前页面SOP可读的可见同源内嵌文档，最多4份，共享12000字/40链接/10000节点上限；跨源/隐藏/沙盒隔离内页跳过，沿用原生平坦回执校验，不增加host权限。用户需重新准备并重新加载扩展，EXE不能自动覆盖已安装扩展。只读已打开页面不等于完整邮箱同步/全关注更新；没有可见未读/时间证据时说明未知。新增网站由用户授权，不用直播API冒充视频动态。

验收：用户两句与表达变体；不同邮箱、同站多账号、显式域名/品牌、未知及伪域名；错误模型工具/过时方法、目标缺失/多目标、无标签/多标签/页面加载、取消/撤销/注入/不留存；真实Conversation接线。因涉及目标权限守卫，冻结后Windows verify:full、必要定向、最终Release/NSIS/桌面与镜像/哈希核对。不访问真实邮件或账号，不默认付费模型调用；原生观感及真实Provider效果集中自然验收，正式2.0.0/M12不变。
