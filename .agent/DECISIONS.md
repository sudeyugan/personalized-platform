## DEC-009：M6 改为自动门禁优先，并以正文资料标记驱动 AI 脱敏

- 日期：2026-08-11
- 状态：已确认并实施
- 背景：用户反馈十项场景和连续七天试用过于繁琐，希望之后尽量少人工验收；同时希望从正文选词直接建立资料并用于 AI 作图脱敏。
- 决定：移除 M6 固定场景、连续天数、环境矩阵和跨设备演练门槛；保留自动质量门禁，安装后按真实工作方式自然体验。正文使用 Tiptap `entityReference` mark 关联人物、地点或事件，可直接建档；AI 调用前默认只替换已标记资料并显示实际发送预览。
- 备选方案：保留打卡但改为可选；用名称匹配自动识别全部敏感词；在 provider 服务端脱敏。
- 选择理由：降低用户验收负担；显式标记比名称猜测更可控，也能同时服务资料沉淀、反向引用和隐私预览，且不要求把原文交给额外服务处理。
- 影响：M7 不再被七天或跨设备人工项阻断；旧 `settings.acceptance` 不再新写入。脱敏保护边界是“已标记资料”，未标记敏感信息必须通过发送预览识别。
- 用户确认：用户在 `1.0.0` 体验反馈中明确提出以上两项变化。
- 关联：`docs/体验反馈与需求补充.md`、`EntityReferenceMark.ts`、`entityPrivacy.ts`、`docs/1.0.0-验收与发布说明.md`

## DEC-008：可移动资料库与本机秘密使用不同根目录

- 日期：2026-08-09
- 状态：已实施
- 背景：M6 首次向导需要允许用户选择资料库目录或接入已有资料库，同时完整备份和跨机器恢复不能带走本机 API Key。
- 决定：应用数据目录保存 `library-location.txt` 指针和 Windows DPAPI 秘密；SQLite、素材、恢复草稿、vault 与默认备份统一使用资料库根目录。首次配置执行绝对路径和写探针检查，已有资料库不做直接原地搬迁。
- 备选方案：全部数据固定在 AppData；秘密与资料库一起移动；自动移动已有资料库。
- 选择理由：兼顾用户可控位置、已有资料库接入和秘密隔离，并避免在缺少中断恢复协议时实施高风险目录搬迁。
- 影响：跨设备使用完整备份恢复，API Key 必须在新设备重新配置；已有库改位置是明确已知限制。
- 用户确认：属于用户已同意的 M6 首次向导、跨机器恢复与安全范围。
- 关联：`storage_root.rs`、`secret_repository.rs`、`docs/1.0.0-验收与发布说明.md`

## DEC-010：M7 音频入库与伙伴双层授权边界

- 状态：已实施（延续已确认的本地优先与逐项授权基线）

## DEC-014：开发验证、候选打包与正式发布解耦

- 日期：2026-09-14
- 状态：已确认并实施
- 背景：每个小补丁都执行前端全量、Rust/Tauri、NSIS、哈希和多文档收口，耗时及上下文成本与改动风险不成比例；同一公开版本反复覆盖安装包也不利于追溯。
- 决定：普通开发默认不跑自动测试，优先完成 coding 并由用户实际体验；复杂逻辑或易复发缺陷才运行少量定向测试。UI 批次门禁只做静态检查与 Web build，前端全量和 Rust 测试留给跨层高风险或正式大版本。CI 只在 PR、发布标签或手动触发。普通任务只更新事实变化的文档。
- 备选方案：所有补丁继续完整发布；完全依赖 Git diff 自动选择门禁。
- 选择理由：保留高风险和正式发布的完整证据，同时去除低风险迭代的重复构建；当前仓库尚无提交，不能安全依赖 Git diff 自动降级。
- 影响：`verify:quick` 为可选定向测试，`verify:ui` 不跑测试，`verify:full` 保留前端/Rust 全量；`release:build` 与正式发布继续独立。公开版本采用不可变二进制，发布后修复使用新补丁版本。
- 用户确认：用户明确同意按该方案修改。
- 关联：DEC-011、R-016、`AGENTS.md`、`.agent/QUALITY_GATES.md`、`docs/工程文档自动化.md`

- 背景：全画布差分要求 AI 在 1024×1536 画布中保持像素坐标，素材制作成本高且容易漂移。
- 决定：角色包 v2 支持局部透明 PNG 通过资源的 slot 名称绑定 character.json 中的统一坐标，并允许可选 offset；未声明 slot 的字符串或对象继续按旧版全画布渲染。控制器、状态机、眨眼和动作播放语义保持不变。
- 备选方案：继续只用全画布差分；把各部位坐标硬编码进控制器或 React 组件；强制一次性迁移旧角色。
- 选择理由：把素材状态与定位职责分开，同时保持旧角色零迁移，并为眉毛、嘴巴、覆盖层和后续 Sprite 类型复用同一机制。
- 影响：动作序列帧暂时仍使用完整角色画布；Slot 尺寸只用于参考、校验和调试，不强制拉伸图片；Renderer 注册表为将来增加 Live2D 实现保留最小入口，但本轮不接入 SDK。
- 用户确认：用户明确要求直接按该兼容演进方案修改代码。
- 关联：R-021、`docs/product/03-数据模型与文件规范.md`、`桌面角色_差分立绘与固定动作序列帧_Codex任务说明.md`
