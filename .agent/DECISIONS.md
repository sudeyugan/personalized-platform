## DEC-009：M6 改为自动门禁优先，并以正文资料标记驱动 AI 脱敏

- 日期：2026-08-11
- 状态：已确认并实施
- 背景：用户反馈十项场景和连续七天试用过于繁琐，希望之后尽量少人工验收；同时希望从正文选词直接建立资料并用于 AI 作图脱敏。
- 决定：移除 M6 固定场景、连续天数、环境矩阵和跨设备演练门槛；保留自动质量门禁，安装后按真实工作方式自然体验。正文使用 Tiptap `entityReference` mark 关联人物、地点或事件，可直接建档；AI 调用前默认只替换已标记资料并显示实际发送预览。
- 备选方案：保留打卡但改为可选；用名称匹配自动识别全部敏感词；在 provider 服务端脱敏。
- 选择理由：降低用户验收负担；显式标记比名称猜测更可控，也能同时服务资料沉淀、反向引用和隐私预览，且不要求把原文交给额外服务处理。
- 影响：M7 不再被七天或跨设备人工项阻断；旧 `settings.acceptance` 不再新写入。脱敏保护边界是“已标记资料”，未标记敏感信息必须通过发送预览识别。
- 用户确认：用户在 `1.0.0` 体验反馈中明确提出以上两项变化。
- 关联：`docs/体验反馈与需求补充.md`、`EntityReferenceMark.ts`、`entityPrivacy.ts`、`docs/1.0.0-验收与发布说明.md`

## DEC-008：可移动资料库与本机秘密使用不同根目录

- 日期：2026-08-09
- 状态：已实施
- 背景：M6 首次向导需要允许用户选择资料库目录或接入已有资料库，同时完整备份和跨机器恢复不能带走本机 API Key。
- 决定：应用数据目录保存 `library-location.txt` 指针和 Windows DPAPI 秘密；SQLite、素材、恢复草稿、vault 与默认备份统一使用资料库根目录。首次配置执行绝对路径和写探针检查，已有资料库不做直接原地搬迁。
- 备选方案：全部数据固定在 AppData；秘密与资料库一起移动；自动移动已有资料库。
- 选择理由：兼顾用户可控位置、已有资料库接入和秘密隔离，并避免在缺少中断恢复协议时实施高风险目录搬迁。
- 影响：跨设备使用完整备份恢复，API Key 必须在新设备重新配置；已有库改位置是明确已知限制。
- 用户确认：属于用户已同意的 M6 首次向导、跨机器恢复与安全范围。
- 关联：`storage_root.rs`、`secret_repository.rs`、`docs/1.0.0-验收与发布说明.md`

## DEC-010：M7 音频入库与伙伴双层授权边界

- 日期：2026-08-12
- 状态：已实施（延续已确认的本地优先与逐项授权基线）
- 背景：跨页面音乐不能依赖导入源路径；伙伴上下文又不能因作品解锁或普通授权而自动读取加密正文。

## DEC-035：内容外发统一经过本地隐私网关，中文模型先评测后接入

- 日期：2026-09-22
- 状态：已确认并实施第一阶段
- 背景：现有信任层能控制是否联网和是否携带上下文，但不能阻止用户输入、历史或 Tool Result 中的手机号、真实姓名、路径、Key 等内容传播到外部 Provider。
- 决定：所有外部模型请求统一经过 Egress Gateway；规则与校验器检测常见中文 PII 和秘密，私密词典补足用户明确标记的专名，同一 Agent 回合使用稳定化名并在本机恢复。SECRET 硬阻断，普通隐私按平衡/严格模式预览确认。语音原始音频边界单独明示，转写后文本和 TTS 文本接入保护。
- 备选方案：只靠 Prompt 提醒模型；直接捆绑一个中文 NER；仅过滤当前输入；把隐私过滤写进每个 Provider。
- 选择理由：本地确定性规则体积小、可解释且先覆盖最高风险内容；统一 Provider 包装能覆盖 Agent 多步回传并保持 Tool/权限边界。中文模型公开基准、许可证和地区适配仍不充分，先建立一隅语料基准更稳妥。
- 影响：设置新增私密词典和发送前确认模式；朝问默认自动使用过滤，伙伴对话可预览；未来本地 PII 模型只能作为检测器插件接入网关，不得直连业务或网络。
- 用户确认：用户明确要求先实现第一阶段，并调研更适合中文的模型。
- 关联：DEC-025、DEC-034、R-012、R-025、R-027、R-029

## DEC-035：待机唤醒与声纹完全本地化，验证后才连接云端语音

- 日期：2026-09-22
- 状态：已确认并实施
- 背景：持续把待机麦克风音频发送给 ElevenLabs 会带来额度消耗和隐私外发；用户同时要求自定义唤醒词与声纹识别一步到位。

- 备选方案：持续云端转写；只做本地唤醒词不做声纹；使用云端声纹服务；把声纹当作操作授权。
- 选择理由：本地待机可消除闲置云端音频与额度消耗；模型按需下载避免安装包再增加约 43 MB；复用 DPAPI 和现有短期 token 能保持长期密钥不进入子窗口。

- 用户确认：用户明确要求支持自定义唤醒词，并希望本地声纹识别一步到位；随后确认开始实现。

## DEC-034：动态 WebM 使用多片段语义动作库，隐私与安全共享信任边界但保持独立策略

- 日期：2026-09-22
- 状态：已确认并实施
- 背景：单个待机/表情 WebM 已能稳定替代初期 Live2D，但无法承载更丰富的静息变化、表情和姿势；同时在线模型、语音和 Agent 写入需要让用户清楚控制数据外发与执行能力。
- 决定：把原来的 `state → assetId` 兼容演进为 `state → assetId[]`。待机在片段自然结束后轮换并避开紧邻重复，交互/表情/姿势状态由通用 `companion.set_state` Tool 选择，缺失状态回退待机。隐私和安全在 UI/请求链路上组成统一信任边界，但隐私策略只负责外发、上下文和留存，安全策略继续负责 capability/risk、scope、确认和审计。
- 备选方案：每个状态只保留一个视频；按固定时间强制随机切片；用单一“允许 AI”开关同时代表数据外发和执行权限；立即接入 Live2D SDK。
- 选择理由：多片段动作库能在不引入 Live2D SDK 的情况下提高生命感，并保持用户上传素材的低门槛；两类策略如果合并成单一开关会混淆“数据能否离开本机”和“模型能否执行动作”，难以审计也容易误授权。
- 影响：旧单段 WebM 无需迁移素材即可继续使用；后续新增 Live2D Renderer 时可复用语义状态层。任何新 Provider 必须先接入外部处理总出口和上下文裁剪，再接入既有 Tool/权限边界。
- 用户确认：用户要求丰富 WebM 表情、姿势与多种静息动作，并允许先调研隐私层和安全层是否合并后实施。
- 关联：DEC-023、DEC-026、DEC-028、R-019、R-022、R-024、R-025、R-027、R-028
