# DEC-094：已填登录状态与聊天链接修复

用户反馈：页面明显已经填入账号密码仍被告知未自动填好；回复链接悬停可点击却没有反应。此轮聚焦两处根因，不重写通用任务内核。

- 登录旧判定只认autofill伪类；匿名公开Coremail模板的账号/密码均autocomplete=off且有placeholder。补浏览器placeholder-shown/required validity布尔状态，不读取value/defaultValue/凭据HTML、不填/选账号；无可靠证据仍停止。最多3秒等异步填充，逐次复核任务/站点/URL，点击前同步重判，原唯一同源HTTPS POST、挑战停止、逐站独立许可及一次点击保持。未能检测不再声称确实没填。
- RichText旧anchor的target=_blank未连接OS打开。主窗/桌宠聊天共享ReplyLink，用户点击调用专用原生命令；主窗与companion-chat标签白名单、HTTPS域名/账号/端口/本地地址/敏感query拒绝、接管互斥，不加载特权WebView/注册模型工具/新授权。失败给固定提示，无原始错误或私人URL。
- 验证内循环只相关前端/扩展测试；隔离真实Edge虚构已填表单不强制autofill标记，空表单/一次登录/新页证据。因认证检测与原生入口按项目安全门禁只批次full一次，任何单项失败先定向处理，不机械重复。
- 收口：代码冻结→检查→Windows候选/桌面→源码与产物核对→已授权origin/main普通推送。不改正式版本/官方哈希/现有授权，不以虚构表单替代真实密码管理器/账号回验。

实施证据：61定向与实际隔离Edge虚构空/已填表单、无autofill标记、一次POST与新收件箱通过。完整检查类型/lint/1118前端通过、Rust宏路径编译失败；修正为原模块命令路径后仅续跑154 Rust/13忽略，通过。不重跑full，Web构建由候选Release覆盖（整体退出0）；桌面/11源镜像/产物哈希已核对，正式版本/官方哈希保持。实际账号和原生桌面链接需自然回验，推送完成事实见PROJECT_STATE。
