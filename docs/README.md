# 文档整合说明

用户提供的两个压缩包承担不同职责，已按以下方式合并，而不是保留两套重复状态：

- `产品与开发文档包 v0.1` 是目标基线，原文统一存放在 `docs/product/`。
- `Agent Development System` 是开发治理方法，根规则放在 `AGENTS.md`，目标、状态、路线图、门禁、决策与风险放在 `.agent/`。
- 两者重叠的路线图、决策和风险信息，以 `docs/product/` 保存产品原始依据，以 `.agent/` 保存随实现更新的当前事实，避免复制整段内容后逐渐不一致。
- `体验反馈与需求补充.md` 按正式版本保存用户体验反馈；同版本补丁直接更新原章节，不新增版本。
- `工程文档自动化.md` 说明机器状态源、生成区块、CI 检查与统一发布命令。

## 文档同步边界

- 普通修复只更新直接受影响的事实或原反馈项，不同步整套 README、Roadmap 和产品文档。
- 版本、里程碑、架构、数据模型或验收状态实际变化时，才更新对应状态、决定、风险和产品实现注记。
- 正式发布由机器状态源和发布命令同步生成区块、安装包路径与哈希。
- 旧门禁和审查流水保存在 `docs/archive/`，不属于日常必读。

开发时先以 `docs/product/01-产品需求文档.md` 与 `02-技术架构.md` 判断产品行为和架构边界，再以 `.agent/PROJECT_STATE.md` 判断当前完成度。M7 记录见 [1.2.0 验收与发布说明](./1.2.0-验收与发布说明.md)；M8 记录见 [2.0.0 验收与发布说明](./2.0.0-验收与发布说明.md)。未经用户确认，不修改产品目标基线。
