## 先看整体

[查看手机概念图](M13_手机概念图.svg)。纯静态SVG、无脚本/外部字体/远程素材；所有课程、记录、任务和文件都是虚构示例。角色轮廓仅用于观察大小、布局和状态，不是新造型定稿；静态分镜不冒称实时动画或可用语音。

已确认：手机保留待办、作业、课表/日程、日记、心情记录与回望、想法工坊、小鱼对话。其他PC模块不因同步协议支持就自动出现。小鱼跨App语音优先，多形态可选，不自动展开对白；跨设备是本机能力的代理执行＋实际文件传递，不做远程桌面。

## 1. 页面结构建议：今日 / 手记 / 小鱼

| 主入口 | 内容与主要动作 | 不做什么 |
|---|---|---|
| 今日 | 下一节课/最近安排；本周未交周作业＋单次截止；待办。进入课表/日历后看完整安排 | 不堆七组模块入口，不显示未来21天周作业墙，不因缺学期数据猜当前课程 |
| 手记 | 按日期回看日记和心情；直接写日记/记心情；进入独立想法工坊长卷 | 同日相邻展示不等于合并记录；不把日记内容送模型或生成情绪好坏分数 |
| 小鱼 | 完整角色与语音交流；文字会话按需；当前设备/远端任务与收到的文件按需展开 | 不自动弹执行日志/表格，不以消息已发代替任务完成，不添加远程桌面 |

设备、连接、模型、隐私与外观设置经页头次级入口打开，不占第四个主导航。三个入口的建议尚待用户选定，不是既定的信息架构。

### 今日：是一页安排，不是一墙卡片

- 页头以日期、简短标题和下一项安排形成主次。课程/日程没有时留白，不合成虚构安排填满。
- 作业按用户现有规则显示本周未交＋单次截止，提交只是本机记录，不向学校网站提交。待办复用周期/配额规则，不退回一个布尔勾选。
- 新建先选待办/作业/日程，手机编辑页只呈现该项字段；保存后回到原位置，不重置导航或滚动。
- 完整课表/月历在次级页，系统返回回到原浏览位置。离线/未同步的状态在相关位置轻提示，未保存/冲突才阻止离开。

### 手记：同一册里保留各自的语义

- 一天一段，日记完整阅读，心情用真实点数显示；没有记录显示未记录，不填零或猜测。
- 心情录入沿用18项、早午晚每次五点；回望保留气泡矩阵/色带及周/月范围，不重新加已淘汰图表。
- 日记/心情/想法各自存储。小鱼不会因它们在同一页就获得自动读取/外发许可。
- 想法工坊进入全屏连续长卷，沿用原选项/自述、分支和手改稿保护；普通记录不强制长时间落墨动画。
- 键盘弹出时收紧装饰与角色，保证正文、保存/返回可见。允许字体放大、深色和减弱动态；手势不是唯一操作入口。

### 纸墨视觉与连续性

暖纸、细墨、低饱和青灰为候选视觉语言。今日以清晰排版为主；手记以日期题签和连续阅读为主；小鱼留出角色空间。用展开关系、保存后的原位落定表达变化，不给每个点击都加仪式动画。正文始终是真实可选文本，不把长篇文字画进Canvas。最终字体、暗色与实际DPI须在手机看，不以本图代替。

## 2. 形态与会话必须分开

| 可见形态（用户已要求） | 本提案的具体呈现（待确认） |
|---|---|
| 不显示 | 不画角色/浮层；是否继续已开启语音由单独控制决定，不能将隐藏误报为停麦 |
| 轻量收起 | 侧边细小墨点/标记，触摸目标比画面大，但不能形成遮住其他App的巨大透明热区 |
| 极小手办 | 有独立小尺寸轮廓，低频抬头/呼吸等动作；不把PC半身直接缩小，不承诺本概念轮廓是最终全身造型 |
| 展开常驻 | 更清楚的角色形态，不自动附带文字气泡或面板；可收起/隐藏 |

同一会话在形态切换中保持，不为每种浮层建立独立聊天。隐藏角色与结束语音是两个动作，菜单和通知都须明确；系统麦克风提示不得掩盖。隐藏时语音是否自动结束，是需要用户选定的策略，不默认永久监听。

### 语音启动建议与状态分镜

建议首版通过明确的“开始语音”动作启动一段会话，保持连续轮次；可随时停止麦克风和播放。点角色本身是否直接开语音尚待用户确认，不能将普通拖动误触发录音。后台唤醒词作为独立能力评估，不把PC唤醒方案直接搬到手机。

| 状态 | 非文字反馈建议 | 必须真实对应的事实 |
|---|---|---|
| 未开会话 | 轻待机，无倾听特效 | 不采集音频，不因待机动作误导在听 |
| 倾听 | 贴近角色的细环/微光，形状变化不只靠颜色 | 当前会话确实已取得麦克风并采集；权限失败不得显示倾听 |
| 处理 | 两枚缓慢交换位置的墨点，小动作暂停 | 已收到本轮输入、仍待处理，不误报说话或执行完成 |
| 回答 | 与实际播放对应的轻脉冲/角色动作 | TTS正在播放，播放失败/结束立即停止 |
| 等确认/失败 | 短暂不同形状提示，可按需打开详情 | 不能只靠装饰或声音藏住权限、费用、高风险确认与失败原因 |

默认不弹对白；静音环境可主动开字幕/文字入口。减弱动态使用静态状态差异。屏幕锁定、通话/音频焦点、网络失败与服务被系统终止的行为须另定义并真机验收，不承诺永远后台可用。语音识别/合成来源、音频是否离开设备、额度和保留方式在接入前说明并确认；已有DeepSeek文字Key不等于已有手机语音能力。

## 3. 云中枢下的设备能力代理

提出请求的设备组织当前任务；目标设备只接收受限、可校验的任务，使用自身已授权应用/API/受控自动化执行。云端负责认证/协调/密文队列，不远程注入脚本，不需要知道浏览器密码。

每个任务至少关联稳定任务ID、发起/执行设备、能力与参数版本、权限范围、有效期、状态和产物引用。具体协议另设计；不能将本节字段当已存在的实现。

建议的任务状态：`待授权/待设备 → 执行中 → 完成/部分完成/失败/过期`。取消须区别“尚未执行已取消”和“已请求停止但可能已有副作用”；重传同一任务不重复执行。换设备执行必须重查能力/授权，不由模型偷偷换目标或把应用结果当指令。

### 首批场景建议（不是应用白名单定稿）

| 场景 | 用户看到的完整流程 | 能证明什么 / 仍缺什么 |
|---|---|---|
| 手机借用电脑已授权浏览器 | 手机提问 → 明确执行设备 → 电脑通过现有受控浏览器查询 → 手机收到整合结果 | 验证真实跨设备应用能力；不只读同步记录，不保证网站登录/兼容成功 |
| A明确选定的文件发送到B | 发起端指定文件和接收设备 → A本机范围核对 → B看到进度 → 文件落在允许位置且校验通过 | 验证实际文件而非路径；不授予全盘扫描或默认自动执行 |
| A独有应用处理文件并交回 | B明确任务/输入 → A的应用实际处理 → 产物核验 → 传给B | 用户还未指定真实应用，先保留为验收模板，不虚构已有转换/办公等连接器 |

实施顺序建议先“明确文件传输＋现有应用代理”，再用用户选定应用验证更完整的产物闭环。能力描述、设备路由、参数/权限/结果协议通用；首批用例用于验框架，不将程序写成只认某个网站或软件名称的特判。

不做远程桌面、窗口视频串流或让B用键鼠亲自操控A。不把文件/数据同步等同于外部应用操作权限。

## 4. 文件交接建议

- 一份传输清楚展示发送/接收设备、文件名/类型/大小、进度和状态；这些也可能含隐私，不默认送模型或公开日志。
- 设备已配对不等于允许接收任何文件。建议用户先为可信设备配置接收目录与限额，范围内普通文件不反复确认；覆盖已有文件、可执行内容、超范围另处理。这是待确认策略，不改变现有权限。
- 建议默认生成不冲突的新文件名，不覆盖原文件；传输中使用临时文件，完成后核对实际字节/校验值再发布。保存到本机与已读/已打开分别标记，不自动打开/执行。
- 中断后可继续或取消；取消后不得把半个文件呈现为成品。任务成功但文件失败要分别显示，不重新执行已经成功的应用动作来“重试发文件”。
- 接收设备离线：建议显示等待设备并允许取消/过期；是否在云端临时存密文及保留期/配额另确认。服务器资源未选，不硬编码承诺大文件上限、费用或始终直连。
- 已接收文件是用户本机副本；撤销设备不能抹除它。同步不是备份，文件转移也不应默认删除A原件。

## 5. 聊天、记忆与隐私：会话连续性已确认，其他范围仍需区分

用户已同意普通会话在可信设备间端到端加密同步，另有仅本机会话。长期记忆的跨端范围尚未选定，不随此同意全部共享。聊天回看、任务上下文、模型输入分别控制，同步历史不等于每次全量送模型。

私人网页原文、密码/Cookie/APIKey、未授权文件正文不搭便车进入会话同步或模型。查询回合原文不持久化的既有偏好保持；跨端任务仅保留必要状态/产物交接事实，具体保留期另定。若用户不接受会话同步，仍能做设备代理与文件传输，不以开放全部历史为前提。

## 6. 设计与实现的收口条件

| 批次 | 要看见的结果 | 不能据此宣称 |
|---|---|---|
| 当前体验草案 | 静态手机主页面、四形态/状态分镜、任务和文件完整流程可讨论 | 安卓已重构、角色/语音可运行或云端已部署 |
| 手机交互原型 | 已确认页面/形态可在实际尺寸体验，字体/返回/键盘/减弱动态不破坏内容 | 真机后台/耗电已通过，或所有PC功能迁移 |
| 代理与文件隔离原型 | 虚构数据、两设备身份下实际请求/执行/文件字节和失败路径可核对 | 任意应用通用、真实跨网/账号/手机已验收 |
| 集中真机交付 | 用户选定应用＋真实Windows/Android跨网、断网恢复、覆盖升级与权限边界通过 | 多人商业服务或远程桌面已纳入 |

三入口/视觉、轻点开启语音/可结束、普通聊天跨端连续与私密会话三项已获认可，用户要求本批做到M13.3再集中验收。提前需要确认云资源/购买部署与手机语音服务/音频外发，手机型号可后补；文件策略和真实应用场景留给M13.4准备，不在本批提前实施。阶段内不要求用户逐个确认微小修改。
