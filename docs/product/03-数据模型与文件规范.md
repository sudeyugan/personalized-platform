# 一隅：数据模型与文件规范

版本：0.1  
目的：让数据库、编辑器、导入导出和备份拥有共同语言。

## 1. 建模原则

- 所有实体使用 UUID/ULID，不使用标题或路径作为身份。
- 时间统一保存 UTC，界面按本地时区显示；用户叙事时间另用可模糊的时间结构。
- 数据行包含 `created_at`、`updated_at`，可恢复删除使用 `deleted_at`。
- 内容结构、应用 schema 和备份格式均有独立版本号。
- 数据库只保存相对路径和逻辑素材 ID。
- 加密作品的真实元数据与内容不进入普通数据库和全文索引。

## 2. 核心实体关系

```text
Workspace
├─ LayoutProfile
├─ ModuleSetting
├─ Work
│  ├─ Volume
│  │  └─ Chapter
│  │     ├─ DocumentCurrent
│  │     ├─ DocumentVersion
│  │     ├─ AssetLink
│  │     └─ EntityLink
│  ├─ Person
│  ├─ Place
│  ├─ TimelineEvent
│  └─ Asset
├─ DiaryEntry
├─ PermissionGrant
├─ AiGeneration
└─ BackupRecord
```

## 3. 主要表（逻辑模型）

### 3.1 `works`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | text PK | 作品 ID |
| kind | text | memoir / novel / custom |
| title | text | 非加密作品标题 |
| description | text nullable | 简介 |
| cover_asset_id | text nullable | 封面 |
| encrypted | boolean | 是否使用独立 vault |
| vault_id | text nullable | 加密容器 ID；不含真实标题 |
| sort_key | text | 排序键 |
| created_at / updated_at / deleted_at | datetime | 生命周期 |

加密作品锁定时，`title`、`description`、`cover_asset_id` 必须为空；UI 只显示本地化的“加密作品”占位文本。

### 3.2 `volumes`

`id`、`work_id`、`title`、`description`、`sort_key`、时间字段。卷为可选层级；没有卷的章节直接属于作品。

### 3.3 `chapters`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | text PK | 章节 ID |
| work_id | text | 所属作品 |
| volume_id | text nullable | 所属卷 |
| title | text | 标题 |
| document_id | text | 当前正文 ID |
| cover_asset_id | text nullable | 印象图/封面 |
| word_count | integer | 已提交版本字数缓存 |
| sort_key | text | 支持拖动排序的稀疏键 |
| status | text | draft / revised / done / archived |
| created_at / updated_at / deleted_at | datetime | 生命周期 |

### 3.4 `documents_current`

- `id`
- `owner_type`：chapter / diary / person_note / place_note / event_note
- `owner_id`
- `schema_version`
- `content_json` 或加密引用
- `plain_text_cache`（非加密内容，用于搜索和统计）
- `revision`（单调递增，用于乐观并发）
- `committed_at`

### 3.5 `document_versions`

- `id`、`document_id`、`revision`
- `content_blob`（压缩 JSON；加密作品存于 vault）
- `schema_version`
- `reason`：timer / close / manual / import / restore / migration
- `label`、`pinned`
- `word_count`、`created_at`
- `source_version_id`（恢复或派生来源）

唯一约束：`document_id + revision`。

### 3.6 `diary_entries`

- `id`、`entry_date`、`title`、`document_id`
- `mood` nullable、`weather` nullable、`tags`
- `encrypted`、`vault_id`
- 时间字段

同一天允许多篇，不能把日期作为主键。

### 3.7 `people`

- `id`、`work_id nullable`（为空表示跨作品资料）
- `name`、`aliases_json`、`avatar_asset_id`
- `summary`、`custom_fields_json`、`tags_json`
- 时间字段

人物关系使用独立 `person_relations`：`from_person_id`、`to_person_id`、`relation_type`、`description`、有效时间。

### 3.8 `places`

- `id`、`work_id nullable`
- `name`、`aliases_json`、`description`
- `region`、`address`、`cover_asset_id`
- `custom_fields_json`、`tags_json`、时间字段

### 3.9 `timeline_events`

| 字段 | 说明 |
|---|---|
| id / work_id | 身份与范围 |
| title / description | 事件信息 |
| time_precision | exact / month / year / approximate / unknown |
| start_date / end_date | 能确定的日期部分 |
| display_time_text | 用户原始写法，例如“约 1998 年夏天” |
| sort_time | 用于稳定排序的内部值 |
| manual_order | 同一时间段内手动顺序 |

人物、地点、章节与事件的多对多关系统一放入 `entity_links`。

### 3.10 `entity_links`

- `id`
- `source_type`、`source_id`
- `target_type`、`target_id`
- `relation_type`：mentions / occurs_at / involves / related / source_for
- `anchor_json` nullable：正文节点 ID、选区或块 ID
- `created_at`

应用服务保证双向查询，不复制两条方向相反的数据。

### 3.11 `assets`

- `id`、`media_type`、`mime_type`
- `storage_path`（相对路径）
- `original_filename`（展示用途，须清理）
- `sha256`、`byte_size`、`width`、`height`、`duration_ms`
- `thumbnail_path`
- `origin`：import / paste / ai / generated_theme / music
- `metadata_json`、时间字段

内容寻址去重可在后期增加；初版不能因哈希相同就自动删除用户可见的两份素材记录。

### 3.12 `ai_generations`

- `id`、`kind`：chapter_impression / theme_background / character_art
- `provider_id`、`model_id`
- `source_type`、`source_id`、`source_revision`
- `prompt`、`negative_prompt`、`parameters_json`
- `status`、`error_code`
- `result_asset_ids_json`
- `created_at`

对加密来源：记录也应进入 vault；普通数据库只保留匿名作业状态且不可反推出标题。

### 3.13 `permission_grants`

- `id`
- `principal_type`：module / companion / plugin / ai_provider / cloud_provider
- `principal_id`
- `resource_type`、`resource_id`
- `action`：read / write / generate / export / network
- `scope`、`expires_at`、`revoked_at`
- `granted_at`、`last_used_at`

权限必须可枚举、撤销和审计。

### 3.14 界面与模块

- `modules`：安装状态、版本、启用状态、数据 schema。
- `layout_profiles`：名称、当前/默认标志、布局 JSON。
- `navigation_preferences`：模块入口顺序、分组、隐藏。
- `session_state`：窗口、标签、固定资料、滚动与光标（不保存锁定作品的真实标题）。
- `theme_settings`：设计令牌覆盖与背景素材 ID。

## 4. 编辑器 JSON 规则

示例：

```json
{
  "schemaVersion": 1,
  "type": "doc",
  "content": [
    {
      "type": "heading",
      "attrs": { "level": 1, "nodeId": "01J..." },
      "content": [{ "type": "text", "text": "第一章" }]
    },
    {
      "type": "paragraph",
      "attrs": { "nodeId": "01J..." },
      "content": [{ "type": "text", "text": "那一年……" }]
    },
    {
      "type": "imageAsset",
      "attrs": {
        "nodeId": "01J...",
        "assetId": "01J...",
        "alt": "旧照片",
        "caption": "家门前",
        "width": 720
      }
    }
  ]
}
```

规则：

- 图片节点只引用 `assetId`，不保存绝对文件路径或 base64 大图。
- 可关联段落/图片的节点必须有稳定 `nodeId`。
- 未知 schema 版本禁止写回；先迁移或只读打开。
- 导出器不得依赖 React DOM，而应读取规范 JSON/AST。

## 5. 资料库目录

建议默认位于 Windows 用户应用数据目录，并允许用户选择独立资料库位置：

```text
YiyuLibrary/
├─ library.json                  # 资料库标识与格式版本，无私密标题
├─ db/
│  └─ yiyu.sqlite
├─ assets/
│  ├─ images/<asset-id>.<ext>
│  ├─ thumbnails/<asset-id>.webp
│  └─ audio/<asset-id>.<ext>
├─ vaults/
│  └─ <vault-id>/                # 加密作品容器
├─ recovery/
│  └─ drafts/                    # 崩溃恢复；加密内容同样加密
├─ backups/                      # 可改为用户指定目录
└─ logs/                         # 默认不含正文或真实私密标题
```

应用不得让用户直接编辑数据库；但“打开资料库目录”和“导出开放格式”应易于找到。

## 6. 完整备份包格式

扩展名建议：`.yiyu-backup`（实质为 ZIP，但使用专用扩展名）。

```text
backup.yiyu-backup
├─ manifest.json
├─ database.sqlite              # 一致性快照
├─ assets/...
├─ vaults/...                   # 保持加密，不在备份时解密
├─ checksums.sha256
└─ preview.json                 # 仅非敏感统计，便于恢复预览
```

`manifest.json` 最小字段：

```json
{
  "format": "yiyu-backup",
  "formatVersion": 1,
  "appVersion": "0.1.0",
  "databaseSchemaVersion": 1,
  "createdAt": "2026-08-07T00:00:00Z",
  "libraryId": "01J...",
  "counts": { "works": 1, "chapters": 12, "assets": 20 },
  "encryptedVaults": 1,
  "includesHistory": true
}
```

不得包含 API Key、OAuth refresh token、伙伴未授权缓存、解密密钥或明文密码提示。

## 7. Markdown 导出规范

```text
作品名/
├─ README.md                     # 作品信息与目录
├─ 01-卷名/
│  ├─ 001-章节名.md
│  └─ 002-章节名.md
├─ 人物/
├─ 地点/
├─ 时间线.md
└─ assets/
```

- 文件名清理 Windows 非法字符并处理重名；正文内部链接使用相对路径。
- 图片原始文件复制到 `assets/`。
- YAML front matter 保存稳定 ID、章节顺序、日期、标签和关联，外部编辑器可忽略。
- 即使 front matter 丢失，正文和图片仍可阅读。

## 8. DOCX/PDF 导出规范

- 标题 1 为作品名，标题 2 为卷，标题 3 为章节（或根据模板映射）。
- DOCX 使用真实标题样式，不只做视觉加粗，保证以后可重新识别层级。
- 图片嵌入文件，不引用本机路径。
- PDF 嵌入支持中文的字体或使用系统可用字体并做缺字验证。
- 导出模板与界面主题分离。

## 9. 数据迁移

每次迁移：

1. 检查磁盘空间与当前 schema。
2. 创建一致性安全快照。
3. 在迁移日志写 `started`。
4. 在事务中执行可事务化变更；文件变更使用 staging 目录。
5. 验证行数、外键、素材哈希和文档 schema。
6. 标记 `completed` 并更新版本。
7. 失败则回滚数据库和 staged 文件，保留诊断但不记录正文。

编辑器 schema 迁移与数据库迁移分开测试。

## 10. 数据保留与清理

- 回收站默认 30 天；永久删除需二次确认。
- 自动版本默认保留最近 100 个；手动固定版本永久保留。
- 删除章节后，仍被其他内容引用的素材不删除。
- 孤儿素材只在扫描、预览并确认后清理。
- 自动备份清理同时受数量、天数和空间上限控制。
- 对加密作品的永久删除需清除 vault、缓存、恢复草稿、索引和缩略图，并说明无法恢复。

## 11. 0.1.0 当前物理存储映射（2026-08-08）

本文件第 3 节仍是目标逻辑模型。`0.1.0` 的实际物理结构是渐进实现：

| 当前存储 | 内容 | 可靠性规则 |
|---|---|---|
| `yiyu.sqlite / library_state` | 一行完整 `LibraryData` JSON、revision、schema version、更新时间 | `BEGIN IMMEDIATE`、expectedRevision、WAL、`synchronous=FULL` |
| `schema_migrations` | SQLite 迁移版本 1–3 | 幂等执行，拒绝高于应用支持的数据库版本 |
| `chapter_search` | 非回收站章节标题与纯文本 | FTS5 trigram；短于 3 字符时 LIKE 回退；旧库升级后重建 |
| `recovery/drafts/<chapter-id>.json` | 尚未正式提交的章节临时稿 | `.partial` 后原子改名；章节 ID 路径校验；提交成功后清除 |
| 浏览器 localStorage | 开发预览回退 | 版本化 envelope，不作为桌面正式资料库 |

`LibraryData` 已包含作品、卷、章节、版本、人物、地点、事件、模块/主题/布局/导航和会话状态。尚未落地 `documents_current`、`document_versions`、`entity_links` 等独立关系表。M3 新增双向关系前必须制定从单行快照到关系表的兼容迁移，旧数据不得丢失；在迁移完成前，不把当前物理结构描述成最终模型。

## 12. 0.2.0 资料关系物理映射（2026-08-09）

M3 在不破坏 `0.1.0` 快照的前提下把资料关系投影到 SQLite schema v4：

| 表 | 作用 | 一致性规则 |
|---|---|---|
| `people` / `places` | 人物与地点完整 JSON 及常用列 | 保存事务中从权威快照刷新；保留软删除时间 |
| `timeline_events` | 事件、时间精度、排序时间和手动顺序 | `sort_time, manual_order` 索引；未知时间由领域排序置后 |
| `person_relations` | 人物双向关系类型与说明 | 永久删除人物时同步清理；软删除保留关系 |
| `entity_links` | 章节/人物/地点/事件统一关系和正文锚点 | source/target 双索引；支持反向引用与返回原文 |

`library_state` 仍是当前唯一权威快照，五张表是可重建投影。保存时快照、FTS 和资料投影处于同一 SQLite 事务；旧库首次打开会自动建立并填充投影。此设计不是目标数据模型的终点，改为逐实体权威写入前必须增加双向一致性迁移与回滚测试。

## 13. 0.5.0 图片与数据安全物理映射（2026-08-09）

| 当前存储 | 内容 | 安全与一致性规则 |
|---|---|---|
| `assets/<asset-id>/original.<ext>` | JPG/PNG/WebP 原图副本 | 最大 25 MB；随机逻辑 ID；SHA-256；不依赖导入源路径 |
| `assets/<asset-id>/thumbnail.webp` | 统一缩略图 | 前端受控解码后传给 Rust 原子写入；加密作品锁定时不存在普通缩略图 |
| SQLite v5 `assets` / `ai_generations` | 素材和生成 provenance 投影 | 与 `library_state` 同事务重建；候选确认前不写正式记录 |
| `secrets/*.bin` | AI provider API Key | Windows 当前用户 DPAPI；不进入资料快照或 `.yiyu-backup` |
| `vaults/<vault-id>/vault.bin` | 作品标题、正文、版本、关系、图片字节和 AI 记录 | Argon2id 派生、XChaCha20-Poly1305 认证加密、随机 salt/nonce、原子替换 |
| `backups/*.yiyu-backup` | `library.json`、`assets/`、`vaults/`、manifest、校验清单 | `.partial` 后原子改名；SHA-256；恢复前安全备份；拒绝路径穿越 |

实际备份包为了兼容当前快照权威模型使用 `library.json`，而不是第 6 节目标示意中的 `database.sqlite`；数据、素材与 vault 仍能完整恢复，且不会复制 WAL 中间状态。恢复采用“校验 → staging → 保存新 revision → 目录替换”，失败时尝试回滚当前快照和旧附件目录。

开放导出不等同于备份：Markdown 目录同时输出相对路径图片，DOCX/PDF 是外部阅读/编辑交付，导入支持 DOCX/Markdown/TXT 预览后按章写入。加密作品只有在已解锁并经明文导出确认后才能进入开放格式。

## 14. 1.0.0 可配置资料库与资料标记状态（2026-08-11）

- 应用 AppData 保存 `library-location.txt`，指向默认或用户首次选择的绝对资料库根目录；SQLite、`assets/`、`vaults/`、`recovery/` 和默认 `backups/` 统一从该根目录解析。
- `secrets/` 仍固定在 AppData，并由当前 Windows 用户 DPAPI 保护；接入已有资料库或跨机器恢复不会复制 API Key。
- 首次配置执行绝对路径和写探针检查。已有活动资料库不在向导中直接搬迁，避免目录替换中断；改位置通过完整备份恢复到新的空资料库。
- 2026-08-11 同版本补丁移除 `settings.acceptance` 新写入和界面；旧资料打开时忽略历史验收记录，不影响正文、资料或备份兼容性。
- `settings.backup` 保存最近自动备份成功日期或失败原因。只有桌面端备份命令成功或确认当日备份已存在，才记录成功日期。
- Tiptap 正文以 `entityReference` mark 保存资料标记，属性为 `entityType`、`entityId` 和显示标签；章节到资料的反向引用继续写入 `entityLinks`，选词直接建档使用现有人物、地点、事件模型。
- AI 印象图调用前在前端遍历正文 JSON，仅将已标记资料按实体 ID 稳定替换为匿名占位符；预览文本就是 provider 实际收到的正文片段。原正文、资料名和 Tiptap JSON 不因脱敏而改写。

## 15. 1.2.0 音乐与伙伴状态（2026-08-12）

| 当前存储 | 内容 | 安全与一致性规则 |
|---|---|---|
| `audio/<track-id>.<ext>` | 导入音频副本 | 逻辑 ID 路径校验、MIME 白名单、最大 200 MB、SHA-256、原子写入；不依赖或修改源路径 |
| `LibraryData.tracks` | 标题、艺术家、文件名、MIME、大小、哈希、回收站时间 | 二进制只经受控 command 读取；永久删除同步清理四层上下文和播放会话 |
| `LibraryData.musicContexts` | 全局/作品/章节/专注的有序 track ID | 打开旧资料时补默认空结构；不存在或已删除 track 自动过滤 |
| `LibraryData.companion` | 名称、静态表情、provider 配置、逐项权限、最近 100 条对话 | 默认权限为空；自定义 provider 未确认协议不发送；对话不作为长期记忆 |
| 仅内存 `temporaryCompanionWorkIds` | 加密作品本次解锁会话的伙伴许可 | 不写 SQLite/备份；锁定作品或全部锁定时清除；持久授权不能替代该许可 |

`.yiyu-backup` 从 `1.2.0` 起同时包含 `audio/`，沿用清单哈希、路径围栏、staging 和恢复前安全备份。provider 秘密仍不进入快照；当前伙伴配置不包含 API Key。
## 16. 2.0.0 伙伴成长实现注记（2026-08-17）

- `companion.appearance` 保存发型、服装和可选正式立绘素材 ID；`desktop.visible` 只保存用户显示偏好。
- `companion.memories[]` 保存内容、来源类型/说明、创建与更新时间、0–100 置信度、显式授权状态和可选来源作品。删除采用物理移除，确保后续上下文无法再次注入。
- `companion.personality` 保存温暖/好奇/主动权重；`growth.logs[]` 保存每次变化前后完整快照、原因和时间，支持确定性回退。
- 旧资料库规范化时补齐空记忆、默认形象、默认关闭桌面窗口/成长和初始性格，不改写既有正文、音乐或伙伴消息。

## 17. 2.0.0 标准角色包映射（2026-08-19）

- `companion.desktop.characterPackage` 保存版本、角色 ID/名称、统一画布、差分语义映射、表达式映射和动作 FPS/循环设置；外部相对路径在导入后转换为素材逻辑 ID，不保存用户原始绝对路径。
- 主体、眼睛、眉毛、嘴巴、覆盖层和动作帧继续使用现有 `Asset` 与 `assets/images/<asset-id>.<ext>` 物理仓储，因此自动进入完整备份和哈希校验；被角色包引用的素材不计为孤儿。
- 动作帧在导入时按数字自然顺序固化为 `frameAssetIds[]`。缺图、无效 JSON、非统一画布、空动作目录或 1–60 之外 FPS 会在写入角色配置前拒绝。
- 当前角色素材白名单只驻留 Rust 进程内存，应用重启后由主窗口根据已保存角色包重新注册；桌面窗口不能自行扩大清单。

### 17.1 局部 Sprite 与 Slot（兼容扩展）

- characterPackage.version 2 可增加 renderer.type: sprite 与 slots。Slot 坐标以角色逻辑画布左上角为原点，保存 x/y 和可选的参考 width/height。
- 差分资源既可继续使用旧字符串路径或素材 ID，也可使用 { src|assetId, slot?, offset? }。字符串或未声明 slot 的资源沿用全画布 (0,0)；声明 slot 的局部 PNG 使用 slot.x/y + offset.x/y。

## 20. Agent 审计与立绘视觉迁移（2026-09-18）

- `companion.desktop.visual` 是当前显示来源，支持 portrait、video，以及未来预留的 live2d。video 以 `celebrating / concerned / greeting / idle / listening / looking / nodding / shy / sleepy / speaking / stretching / yawning` 十二类语义状态保存 WebM 素材 ID 列表；`desktop.videoAssets` 保留首段兼容映射，使切回静态立绘后配置不丢失。旧 `thinking / happy / surprised / sad / annoyed / agreeing` 在资料加载时迁移到最接近的新状态。被引用素材不计为孤儿，永久删除时同步清空引用。
- companion.desktop.toggleShortcut 保存桌面伙伴显隐快捷键；空字符串表示关闭，默认 CommandOrControl+Alt+Y。
- companion.desktop.quietShortcut 保存安静穿透往返快捷键；默认 CommandOrControl+Alt+T，第一次进入安静穿透，再次按下恢复切换前的互动或普通窗口模式。
- `companion.provider.providerId` 支持 `mock | deepseek | custom`；`settings.ai.providerId` 支持 `mock | openrouter | custom`。配置只保存 endpoint/model，DeepSeek 与 OpenRouter API Key 分别进入独立 DPAPI secret，不进入资料库、日志或备份。
- 旧 `companion.desktop.characterPackage` 不删除、不强制迁移，但不再是活动显示来源。这样旧资料库可以无损打开，同时新资料只需要一张透明 PNG/WebP。
- `companion.agentAudit` 最多保留最近 300 条 Tool 审计：时间、session ID、tool name、参数形状、权限结论、状态、耗时和错误码。字符串参数只记录长度标记，不记录实际问题、搜索词、正文或 Tool Result；API Key、token、password、secret 与 content 字段强制脱敏。
- 每轮 Agent 的完整 append-only session event 当前只存在于运行时；普通用户/伙伴文本继续复用最近 100 条 `companion.messages`。第一阶段不承诺跨重启 replay 或恢复未完成的 Tool Loop。
- 旧资料库规范化时补 `visual: { type: "portrait", assetId: appearance.portraitAssetId }` 和空 `agentAudit`，不改写旧图片或聊天。
- `planner.dailyQuestions[]` 最多保留最近 90 条，包含日期、问题、背景、追问、核心主题、balanced/sharp 语气与创建时间；它不保存用户回答。用户主动写下时才把带日期标记的内容合并到当天 `diaryEntries`。
- `companion.voice` 分开保存 STT、TTS Provider 配置与自动朗读偏好；API Key 不进入该对象。当前只有接口和安全失败实现，未选择服务商前不采集音频。
- Slot 的宽高只用于制作参考、校验和开发调试；Runtime 根据 PNG 原始像素尺寸相对角色画布绘制，不把图片强制拉伸至 Slot。
- 主体与动作序列仍建议使用完整角色画布；动作帧继续按自然文件名顺序固化。版本 1 数据无需迁移，读取和备份语义不变。
- 实际配置示例见 [character-slot.example.json](../examples/character-slot.example.json)。

## 18. M9 Planner 数据（2026-09-16）

| 字段 | 内容 | 兼容与计算规则 |
|---|---|---|
| `planner.calendarEvents[]` | 日程 ID、日期、标题、可选时间与备注 | 月历格只显示日程与日记标记；旧存档补空数组 |
| `planner.term` | 学期起始日期、总周数 | 当前为 2026-09-14 起 16 周；课程显示时结合自身 weeks 解析 |
| `planner.courses[]` | 星期、节次、教师、地点、周次与备注 | 截图课程通过 courseImportVersion 一次性导入并按星期/节次/标题去重 |
| `planner.diaryEntries[]` | 日期、标题、正文、更新时间 | 日历只保存索引关系；正文继续由创作空间日记页编辑 |
| `planner.moodEntries[]` | 随机 ID、日期、morning/afternoon/evening 时段、总和必须为 5 的情绪点映射、可选短备注及创建/更新时间 | 每天每时段至多一条，首页保存时覆盖该时段；12 种低饱和颜色融合为色带。旧单一情绪记录按时间归入时段并保留为五枚同色情绪点，同日同时段取最新一条 |
| `planner.todos[]` | 标题、备注、日期、优先级、重复方式、repeatDays、completedDates | 不重复任务使用 dueDate；每日不依赖日期；每周使用星期数组。旧 weekdays 转换为周一至周五 |
| `planner.todos[].quotaPeriod / quotaTarget` | 周期次数任务的天/周/月与 1–99 次目标 | 仅 repeat=quota 时生效；缺失时兼容补为每周 3 次 |
| `planner.todos[].quotaCompletions[]` | 每次完成的随机 ID 与 ISO 时间 | 同一天允许多条；按完成时间动态归入对应周期，达到目标后继续记录超额次数 |

普通重复任务统计不写入资料库：程序从 createdAt 到当前日期枚举有效执行日，以 completedDates 计算累计完成、计划次数和百分比。周期次数任务同样不保存派生汇总，只保存逐次完成日志，并按所查看日期的天、自然周或月份实时计算当前次数、达成、超额和累计；撤销只删除当前周期最近的一条完成记录。
