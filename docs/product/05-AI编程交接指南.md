## 1. 开始前

将本目录完整复制到开发设备。新建代码仓库后，把这些文档放入仓库 `docs/product/`，不要只把其中一篇粘给 AI。

开发环境建议：

- Windows 10/11 64 位。
- Git。
- Node.js 当前 LTS 与 pnpm。
- Rust stable（rustup）。
- Microsoft C++ Build Tools，选择“使用 C++ 的桌面开发”。
- Microsoft Edge WebView2。

Tauri 的当前 Windows 前置条件以 [官方 prerequisites](https://v2.tauri.app/start/prerequisites/) 为准，不要仅依赖本文中的版本描述。

## 2. 给 AI 编程工具的固定上下文

每次新会话先要求 AI 阅读：

1. `docs/product/README.md`
2. `docs/product/01-产品需求文档.md`
3. `docs/product/02-技术架构.md`
4. 与当前任务相关的路线图和数据模型章节

可以使用以下开场提示：

```text
你正在开发 Windows 桌面应用「一隅」。请先完整阅读 docs/product 下的 README、PRD、技术架构、数据模型和路线图。当前只执行我指定的里程碑任务，不提前实现后续模块。

必须遵守：本地优先；写作数据不可锁死；React 不直接访问数据库或资料库文件；持久化经过 Rust service/repository；未启用功能不显示；第三方插件代码在第一阶段不加载；所有正文持久化、迁移、加密和备份修改必须带测试。

开始编码前，请说明：本任务对应的需求条目、计划修改的层、数据风险、验证方式。若发现文档冲突，先列出冲突并停止做不可逆的数据结构决定。
```

## 3. 首批任务单（历史启动清单，已完成）

不要一次要求 AI “完成整个软件”。按下列顺序，一次完成并验收一个任务。

### Task 001：仓库与开发环境

- 初始化 pnpm workspace。
- 创建 `apps/desktop` 的 React + TypeScript + Vite + Tauri 2 项目。
- 建立 `packages/contracts`、`packages/editor-schema`、`packages/ui`。
- 加入格式化、lint、前端测试、Rust 测试和最小 CI。
- 生成开发说明，确保全新机器可复现。

完成定义：`pnpm install` 后一条命令启动；一条命令运行全部测试；一条命令构建 Windows 开发安装包。

### Task 002：架构骨架

- 建立 command → service → repository 分层。
- 添加 health check command，前端显示数据库与资料库状态。
- 创建 Tauri capabilities，主窗口只获得最小命令权限。
- 禁止前端直接引入 SQLite 或 Node 文件系统 API。

完成定义：测试证明 UI 只能通过受控 command 获取 health 数据；权限文件有解释。

### Task 003：SQLite 与迁移

- 建立 schema migration runner、迁移日志和测试数据库。
- 创建 workspace、modules、layout profiles 的首批表。
- 开启外键并实现事务 helper。
- 定义前置快照接口，但此任务不必完成正式备份。

完成定义：空库升级、重复运行、失败回滚和未知新版本拒绝启动测试通过。

### Task 004：应用 Shell

- 左侧导航、标签栏、主工作区、右侧栏和设置入口。
- 主题令牌、简体中文 i18n、键盘焦点。
- 模块 manifest 注册；写作/设置启用，音乐/伙伴默认关闭。

完成定义：不修改 Shell 组件即可通过 manifest 增加一个测试模块入口。

### Task 005：布局与主题

- 导航显示/隐藏/排序。
- 首页卡片选择。
- 写作与极简布局方案。
- 浅色、深色、安静温暖主题和本地背景图。

完成定义：设置持久化；重启恢复；停用模块不删除测试数据。

Task 001–005 及 M0–M2 已形成 `0.1.0` 交付。继续开发时以第 0 节交接点为准，不重新执行本节。

## 5. 架构守则

AI 提交代码时必须检查：

- UI 是否绕过 service 层直接持久化。
- 是否用绝对路径保存素材。
- 是否把正文、标题、提示词或密钥写入日志。
- 是否把 API Key 放入 `.env` 后又意外提交。
- 是否静默忽略未知编辑器节点或 schema 版本。
- 是否把“接口占位”做成看似可用但会丢数据的功能。
- 是否在未完成插件安全设计时加载外部 JS。
- 是否只有 happy path，没有磁盘满、断网、错误密码和损坏文件测试。
- 是否在导入/恢复/迁移前创建快照。

## 6. 代码审查清单

### 数据改动

- 有迁移、回滚/恢复方案和 fixture。
- 事务边界明确。
- 加密与非加密路径均测试。
- 错误不会被吞掉，UI 能显示可行动信息。

### 编辑器改动

- 中文输入法组合输入正常。
- 10 万字性能没有明显回退。
- JSON schema 与导出器同步更新。
- 历史版本能读取旧 schema 或有迁移。

### 权限/AI 改动

- 使用最小 capability。
- 请求前展示数据范围。
- 撤销权限后缓存失效。
- provider 错误不影响本地正文。

### UI 改动

- 功能可按模块/设置隐藏。
- 键盘可达、焦点明显、中文无截断。
- 空状态不暴露尚未实现的功能承诺。

## 7. 测试数据建议

仓库保留匿名 fixtures，禁止直接提交真实回忆录：

- `short-zh`：约 1,000 字，含标题、列表、引用、图片。
- `long-chapter-zh`：10 万中文字符。
- `memoir-structure`：3 卷、30 章、20 人物、10 地点、50 事件。
- `docx-clean-headings`：规范标题样式与内嵌图片。
- `docx-messy-headings`：只用字号/加粗模拟标题。
- `encrypted-secret-marker`：包含唯一测试明文，用于扫描泄露。
- `corrupt-backup`：缺文件、错误哈希、ZIP 路径穿越等恶意样例。
