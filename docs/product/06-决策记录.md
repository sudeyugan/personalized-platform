# 一隅：决策记录

版本：0.1  
作用：区分已确认需求、建议方案和未来待定事项，防止开发过程中把假设当成决定。

## 1. 已确认的产品决定

| 编号 | 决定 |
|---|---|
| D-001 | 产品是综合个人平台，不以写作定义全部产品。 |
| D-002 | 第一阶段只完整实现写作，其他功能先搭框架或隐藏。 |
| D-003 | 目标平台为 Windows 10/11 桌面端，采用网页式、Notion 类左侧导航布局。 |
| D-004 | 暂定名称「一隅」，整体气质为安静温暖的私人空间。 |
| D-005 | 界面简约，可更换主题、背景图，未来可用 AI 生成背景。 |
| D-006 | 所有模块、导航、首页卡片、播放器和伙伴均可显示/隐藏与排序，并支持多套布局方案。 |
| D-007 | 作品结构为作品 → 卷/分组 → 章节；日记按日期组织。 |
| D-008 | 编辑器采用 Word 连续输入与可移动特殊块结合的混合式富文本。 |
| D-009 | 支持多标签、右侧固定资料卡和重启恢复会话。 |
| D-010 | 人物、地点、时间线采用详细资料卡并与章节双向关联。 |
| D-011 | 第一阶段需要富文本、自动保存/历史、章节目录/字数、资料管理、图片和 AI 配图。 |
| D-012 | AI 配图按章节内容生成印象图，由用户写完后手动触发。 |
| D-013 | 数据本地优先；云端先预留接口；云端 AI 优先，未来支持本地模型。 |
| D-014 | 支持 DOCX、PDF、Markdown＋图片和完整备份包导出；完整备份可恢复。 |
| D-015 | DOCX、Markdown、TXT 可导入，尽量保留章节与图片；不规范文档进入预览确认。 |
| D-016 | 某些作品或日记可以单独加密，锁定时隐藏标题和预览。 |
| D-017 | 自动保存、最近 100 个自动版本、手动永久版本、每日本地备份和恢复前快照按建议执行。 |
| D-018 | 虚拟伙伴未来同时出现在侧栏和桌面，可分别隐藏。 |
| D-019 | 伙伴支持基础角色换装与 AI 生成立绘，之后补充表情和动作。 |
| D-020 | 伙伴性格自然成长，但所有数据读取逐项授权。 |
| D-021 | 音乐分全局、作品、章节、专注四层；本地为主，预留在线接口；自动切章音乐默认关闭。 |
| D-022 | 长期同时支持模块安装、可视化模块创建器和开发者插件。 |
| D-023 | 仅供个人使用，不考虑多人协作和社交发布。 |
| D-024 | 默认简体中文，从第一天保留国际化能力。 |
| D-025 | 开发主要由 AI 编程工具协助，没有既定技术栈。 |
| D-026 | “答案之书”默认开启但可关闭；每个问题只独立随机抽取一次，同一问题不重抽，但可清空后写下新问题。问题不自动保存，只有主动收藏才持久化问题、答案和时间。 |
| D-027 | 周期次数待办保存每次完成的时间日志；按天、自然周或月实时派生目标、达成和超额，跨周期重置当前进度但保留累计记录。 |

## 2. 当前技术建议（可通过 spike 修改）

| 编号 | 建议 | 验证点 |
|---|---|---|
| T-001 | Tauri 2 + React + TypeScript + Vite | Windows 安装、窗口、权限和开发体验 |
| T-002 | Tiptap/ProseMirror 作为编辑器 | 中文 IME、10 万字、图片块、JSON 迁移 |
| T-003 | SQLite + Rust service/repository | 事务、FTS、迁移和一致性备份 |
| T-004 | 作品级独立加密 vault | 锁定后数据库/索引/缓存/日志无明文 |
| T-005 | AI、云、音乐均使用 provider 接口 | mock、更换服务商和未来本地实现 |
| T-006 | 第一阶段只允许可信内置模块 | 未来第三方插件安全模型未完成 |
| T-007 | NSIS 按用户安装包 | Windows 10/11 安装与升级体验 |

若 spike 推翻建议，必须新增 ADR，而不是悄悄替换实现。

### 2.1 M0 验证结论（2026-08-08）

| 建议 | 结论 | 说明 |
|---|---|---|
| T-001 Tauri 2 + React/TS/Vite | 采用 | 已生成 `0.1.0` NSIS |
| T-002 Tiptap/ProseMirror | 采用 | 工具栏、`/` 菜单、版本和 10 万字符序列化基线已覆盖；真实 IME 待人工 |
| T-003 SQLite + Rust 分层 | 采用并渐进实施 | `0.2.0` 为权威工作区快照 + FTS5 + schema v4 资料关系投影；逐实体权威写入留待后续迁移 |
| T-004 独立加密 vault | 调整后采用 | 算法 round-trip 通过，完整 vault/明文扫描留在 M5 |
| T-006 可信内置模块 | 采用 | 写作可启停，音乐/伙伴不可用且不加载外部代码 |
| T-007 NSIS | 采用 | 构建通过，干净 Windows 安装/卸载待验收 |

文档转换结论为“调整”：DOCX fixture 可生成和重开，PDF 可生成和重开，但复杂格式不承诺无损往返；M5 开放前以 Markdown 作为透明兜底。透明伙伴窗口因 capability 隔离未完成而不进入 `0.1.0`。

### 2.2 M3 数据关系结论（2026-08-09）

T-003 继续采用渐进方案：schema v4 为人物、地点、事件、人物关系和统一实体链接建立可索引投影，权威快照和投影在同一事务中更新。旧 `0.1.0` 资料可直接重建投影，不执行破坏性转换；未来改为逐实体权威写入时需另行决策和迁移验证。

## 3. 暂缓事项

- 真实云同步服务商与同步算法。
- 具体在线音乐平台。
- 对话与绘图的具体云端供应商及默认模型。
- 虚拟伙伴最终采用 Live2D、帧动画还是其他渲染方式。
- 伙伴成长算法、主动互动频率和声音供应商。
- 更复杂的抽卡、日报/情报和软件快捷启动的详细规格。
- 模块市场、插件签名与商业分发方式。
- 便携版与移动端。

## 4. 尚待用户体验验证的问题

这些问题无需阻塞 M0/M1，但应在相应里程碑前通过原型确认：

1. 章节树在作品很大时，是持续显示全部章节还是按卷折叠/搜索。
2. 版本创建的实际时间间隔和“显著变更”阈值。
3. 写作页面的默认内容宽度、字体和行距。
4. 时间线默认以列表、纵向轴还是日历形式呈现。
5. AI 印象图发送整章、摘要还是用户选定片段的默认值；加密章节始终需单独确认。
6. 自动备份默认保留天数和最大空间。
7. 加密作品的自动锁定时长。
8. 章节音乐切换时的淡入淡出和恢复逻辑。
9. 伙伴性格变化怎样既自然又让用户可理解。

## 2026-09-18 补充决定

- 伙伴 Agent 的长期资产是应用自己的 Context、Tool Registry、Permission Engine、Session 与 Audit；不把内部链路建立在 LangChain、OpenAI Agents SDK、DeepSeek Harness 或 MCP 上。
- M10 将原“智能创作”统一为“AI 伙伴”；DeepSeek 对话/Tool Calling 已通过官方域名受限 Rust 代理接入，OpenRouter GPT Image 与任意自定义 Provider 仍安全拒绝发送。
- 桌面伙伴由主窗口注册两类可配置全局快捷键：显示/隐藏，以及在安静穿透与此前显示方式之间往返；伙伴窗口不获得全局快捷键权限，立绘与文字标签保持无边框透明呈现。
- 第一阶段只有 ReadOnly Tool；写入、删除、外部访问与系统操作必须在后续新增 capability、风险级别和确认 UI 后才能开放。
- 桌面形象采用单张透明立绘或 9:16 透明 WebM 语义状态，旧差分角色包退出正式路径；未来 Live2D 作为并列 Renderer 接入，不改变 Agent、权限、记忆和业务服务。桌面形象本身承担轻量聊天入口，Agent 只能通过低风险 Tool 选择有限视觉状态。
- 首页“朝问”按北京时间每日生成并保留 90 天主题用于去重；未运行时下次启动补生成，回答仅在主动写下后进入日记。
