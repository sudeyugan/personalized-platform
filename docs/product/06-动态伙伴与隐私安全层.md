## 1. 为什么这样设计

当前动态伙伴已经能按“待机、倾听、思考、回应、轻松、关切、意外”切换透明 WebM，但每个状态只能绑定一个素材。继续直接增加单一状态字段，会很快形成“表情 × 姿势 × 交互阶段”的组合爆炸，也无法让日常待机自然变化。

与此同时，一隅已经存在作品加密、Windows DPAPI 密钥、Tauri 子窗口隔离、Agent Tool Registry、逐次写入确认和脱敏审计，但这些保护分散在不同模块。下一阶段需要一个统一入口回答两个不同问题：

1. **隐私：哪些数据可以被读取、保留或发送到外部服务？**
2. **安全：哪个窗口、模型或 Tool 可以执行什么能力？**

两者不合并成同一个布尔值，而是在同一“信任层”下分别决策。隐私策略先裁剪数据，安全策略再授权能力。

## 2. 调研依据

- NIST Privacy Framework 强调识别数据处理活动、让个人能够管理数据，并以数据最小化和可审计记录降低隐私风险。本项目据此采用明确的外部处理开关、上下文裁剪与本地留存选择，而不是默认把资料库内容全部塞入 Prompt。[NIST Privacy Framework](https://www.nist.gov/privacy-framework)
- OWASP 将过多功能、过多权限和过多自主性视为 Agent “Excessive Agency”的主要根因，并建议在下游系统执行完整授权、保留审计和对高影响行为加入人工确认。本项目继续坚持模型只能调用声明过的 Tool，写入逐次确认，删除、Shell 和任意文件访问不开放。[OWASP LLM06: Excessive Agency](https://genai.owasp.org/llmrisk/llm062025-excessive-agency/)
- OWASP 同时指出确认界面本身可能被不可信内容伪造或诱导。因此确认卡的标题和按钮由应用固定生成，模型只提供经过截断、按纯文本呈现的操作参数；模型输出不能决定安全提示或按钮文案。[OWASP HITL Dialog Forging](https://community.owasp.org/attacks/Lies_in_the_Loop)
- Tauri Runtime Authority 会按窗口、capability、permission 和 scope 拒绝未授权命令；多个 capability 覆盖同一窗口会合并权限。因此主窗口与桌面伙伴继续使用独立 capability，伙伴子窗口不直接获得资料库命令。[Tauri Runtime Authority](https://v2.tauri.app/security/runtime-authority/)、[Tauri Capabilities](https://v2.tauri.app/security/capabilities/)
- Tauri 建议 CSP 只允许可信来源并避免远程脚本。本项目继续只允许本地脚本，网络模型请求由 Rust 白名单代理完成；WebView 仅为透明 WebM 开放本地 `blob:` 媒体和 ElevenLabs 官方实时转写连接。[Tauri CSP](https://v2.tauri.app/security/csp/)
- Windows DPAPI 通常将密文绑定到当前 Windows 登录用户和当前计算机，并带完整性校验。一隅继续只用它保护 API Key；密钥不进入 SQLite、Prompt、日志或备份。[Microsoft CryptProtectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)

这些参考用于工程风险控制，不代表合规认证或法律结论。

## 3. 动态 WebM 动作库

### 3.1 数据模型

从：

```text
语义状态 → 单个 assetId
```

演进为：

```text
语义状态 → assetId[]
```

状态仍表达“为什么播放”，素材只表达“如何表现”。当前动作词表共十八类：原有十二类，加上 `clothes_adjust`、`hands_behind_sway`、`hair_adjust`、`hands_clasped`、`lean_forward`、`playful_sway` 六类自然待机动作。设置页统一为一张动作列表，不再按交互、表情、姿势、自然待机分成四个折叠区；不提供放松肩膀上传槽。播放调度分为四层：

- 常驻层：`idle` 是绝对主状态；第 1 段固定作为 10 秒基础 idle，后 3 段作为轻变化 idle。基础段结束后各有 50% 机会继续基础段或进入变化，变化素材按随机不重复轮换，任何变化结束后强制返回基础段。
- 自动交互层：`listening` 在唤醒成功时立即开始，并跟随用户语音，不再由音乐播放触发，`speaking` 跟随文字回应和 TTS；模型生成与 Tool 执行不再强制切换动作，而是保持当前 `idle` 画面。
- 一次性动作层：语义动作和六类新增自然待机动作都只完整播放一次，随后回到当前应有的主状态；自然待机动作不开放给模型频繁选择。
- 场景层：`sleepy` 在明确休息语境下可持续，深夜也可少量单次穿插。

旧版单素材映射继续在读取时自动转换成单元素数组。旧 `shoulder_relax` 绑定合并到 `stretching`，去重并保留原素材与逐片位置参数，不删除文件。旧动作中 `agreeing → nodding`、`happy → celebrating`、`sad / annoyed → concerned`；旧 `thinking / surprised` 不再错误映射为环顾，原文件仍保留为未绑定素材，可由用户重新指定或清理。

### 3.2 当前播放规则

1. 基础待机至少一段；第 1 段是基础 idle，后续片段是轻变化 idle。基础段结束时 50% 机会进入变化；变化后必回基础，因此长期按片段数计基础约占 2/3、变化合计约占 1/3（不含穿插和交互，非时长占比）。每轮尽量覆盖所有已上传的变化，不紧邻重复同一变化。
2. 唤醒成功后立即使用 `listening`，不等待用户开口或实时转写 partial；唤醒显示伙伴时不触发覆盖倾听的问候，旧表情计时器同步清除。用户说话时同样使用 `listening`，回复生成或 TTS 播放时使用 `speaking`；DeepSeek 生成和 Tool 工作期间保持 `idle`，不再为了很短的处理过程闪切动画。缺少对应素材时回退 `idle`。
3. 纯待机先等待 30–55 秒，再在当前 idle 完整结束的边界穿插一段自然动作，不中途截断。六类新增动作与环顾、伸展采用随机不重复轮换，固定候选下一轮覆盖全部再重新洗牌，避免低权重素材长期用不到；有多个候选时不紧邻重复。动作结束回基础 idle，并重新等待，不连续堆叠动作。22:00–06:00 的哈欠加入轮换，00:00–05:00 的困倦以 12% 概率加入当次候选。只记会话内素材 ID，不预加载全库；普通快照刷新不会重置等待时间。
4. Agent 可通过受控 `companion.set_state` 选择庆祝、关切、点头、害羞和问候等语义动作；六类新增自然动作与 `looking / stretching` 由本地调度，不要求每轮表演。
5. 同一非 idle 状态的多段素材按该状态独立轮换；倾听、说话、显式困倦等持续状态有多段时仅在片尾换片，单段时原地循环。语义表情在回答或整段朗读结束后单次播放，不再被朗读覆盖后直接清掉；取消或新一轮输入不会补播旧反应。
6. 优先级为 `speaking / listening` 自动交互、显式语义动作、自然待机穿插、`idle`。新一轮输入会先取消上一段语义动作；语音真正开始播放到最后一段结束期间，`speaking` 不能被短时动作提前覆盖。

### 3.3 动作触发与约束

| 动作 | 建议触发 | 约束 |
| --- | --- | --- |
| `greeting` | 当日首次显示伙伴、长时间隐藏后重新显示 | 设置数小时冷却，不在每次打开聊天时重复 |
| `looking` | 纯待机时看向周围 | 每次只播一遍，不代表模型思考 |
| `nodding` | 用户确认、完成操作、Agent 表示理解 | 只由语义触发，不随机 |
| `celebrating` | 完成目标、连续习惯达成或明显好消息 | 需要明确积极事件，不因普通寒暄触发 |
| `concerned` | 风险提醒、低落内容或失败结果 | 不自动推断心理状态，只根据当前对话触发 |
| `shy` | 轻松且适合的社交语境 | 低频使用，避免人格表演过度 |
| `stretching` | 纯待机自然穿插 | 每次只播一遍，与下一动作间重新等待 |
| `clothes_adjust` | 纯待机自然穿插 | 均衡轮换，完整播放后回基础 idle |
| `hands_clasped` | 纯待机自然穿插 | 均衡轮换，不与其他动作连续串播 |
| `hair_adjust` | 纯待机自然穿插 | 均衡轮换，避免紧邻重复 |
| `hands_behind_sway` | 纯待机自然穿插 | 均衡轮换，完整播放一次 |
| `lean_forward` | 纯待机自然穿插 | 均衡轮换，避免制造持续注视感 |
| `playful_sway` | 纯待机自然穿插 | 均衡轮换，结束后留出足够待机时间 |
| `yawning` | 22:00–06:00 的均衡待机穿插，或明确疲倦语境 | 白天不自动触发 |
| `sleepy` | 00:00–05:00 少量穿插，或用户明确要求 | 自动穿插只播一遍；显式场景仍可持续，交互立即退出 |

后续实现语义调度时应由本地规则先确定自动状态，Agent 只补充需要理解语义的动作；每个动作保存最近播放时间和冷却时间，避免模型连续调用造成“演戏过度”。动作词表集中定义，未来新增状态时同步声明所属层、循环方式、允许的自动触发来源和回退状态，而不是只增加一个上传槽。

### 3.4 素材建议

- 统一使用接近 9:16 的透明画布；960 × 1708 与 1792 × 3184 都可使用，同一套素材应保持相同尺寸和角色原点。
- 使用静音 VP9 WebM；基础 idle 与 3 段轻变化 idle 统一为 10 秒，其余动作按内容自然收束。所有素材首帧和末帧应与共同原图一致。
- 第一批优先准备基础 idle、3 段轻变化 idle、`listening / speaking`，再按实际素材补自然待机动作；其余动作每类一段即可，不要求制作多个变体。

### 3.5 无闪烁切换

素材采用用户确认的“首帧＝末帧＝共同原图”契约，不做淡化或视觉过渡。片段结束时同步将末帧绘入透明 canvas 兜底；下一段在不可见 pending 层按受控本地 Range 协议解码，经 playing 与 requestVideoFrameCallback 确认首帧呈现后直接接替，再保留兜底两个合成帧才撤除。逐片等比例缩放和横纵位置沿用校准台保存的参数。本次仅调整调度，不改变这条媒体传输与无空帧切换链路。

## 4. 统一信任层

```text
用户意图 / 当前页面
        ↓
Privacy Policy
  - 是否允许外部 AI
  - 是否携带已授权上下文
  - 是否携带最近对话
  - 是否在本地保存对话
  - 本地敏感内容检测与稳定化名
  - 必要时发送前预览
        ↓
Model Provider（仅获得裁剪后的请求）
        ↓
Tool Call
        ↓
Security Policy
  - Registry / schema
  - capability / risk / scope
  - 加密作品临时许可
  - 逐次确认
        ↓
Application Service → Repository
```

### 4.1 第一阶段隐私策略

- `externalAiProcessing`：外部 AI 总开关。关闭后 DeepSeek 对话和自动“朝问”都不能联网；本地 Mock 仍可用。
- `shareAuthorizedContext`：是否把当前已授权作品/章节摘要带给外部模型。关闭后 Tool 权限本身不变化，但模型初始 Prompt 不携带作品和章节标题。
- `shareRecentConversation`：是否把最近对话作为下一轮模型上下文。
- `retainConversationHistory`：是否把新对话长期写入本地资料库。关闭后本轮仍能完成，但重启或新回合不依赖持久历史。
- `outboundReviewMode`：平衡模式只在发现手机号、邮箱、身份证、本机路径或私密词等内容时确认；严格模式每次连接外部模型前都确认。
- `privateDictionary`：用户可以把真实姓名、地点、组织、项目或账号加入本地词典。开启的词条在同一 Agent 回合中稳定替换为 `[PERSON_1]`、`[PROJECT_1]` 等占位符，模型回答和 Tool 参数回到本机后再恢复。

所有外发模型请求统一经过 Egress Gateway。它不仅保护用户当前输入，也保护历史消息、授权上下文，以及 Agent 查询后再次交给模型的 Tool Result。邮箱、手机号、通过校验的大陆身份证/银行卡、IP 和 Windows 路径使用稳定化名；私钥、常见 API Key、Bearer/密码/令牌赋值属于 `SECRET`，直接阻断且不能通过确认放行。发送前预览只展示脱敏后的版本，不记录原文。

语音存在明确边界：待机阶段与伙伴名字绑定的唤醒名和声纹判断由本地 sherpa-onnx 完成，不请求 ElevenLabs token，也不上传待机音频；只有唤醒词命中且声纹通过后，短连续会话内的原始音频才发送给 ElevenLabs STT。唤醒后可选择单轮、短连续或持续对话：单轮在回答结束后回到本地待机；短连续默认保留约 8 秒追问；持续模式保留约 15 秒，追问会续期且整段会话最多约 2 分钟。云端 VAD 的最低人声时长提高到约 450ms，填充音与无意义短转写不提交；朗读打断还需约 500ms 的有效 partial 确认。“先这样 / 结束对话”结束本轮，“藏起来 / 隐藏起来 / 休息吧”还会收起形象。文本规则无法在上传前理解这段聊天录音，但转写完成后的文字、发给 DeepSeek 的请求和发给 TTS 的文字仍经过本地保护。若以后要求聊天音频也完全不外发，需要继续接入本地 STT。

声纹录入使用四段本机录音生成 embedding，原始 PCM 不落盘，embedding 进入现有 Windows DPAPI 安全存储且不进入资料库备份。声纹只用于减少误唤醒，不是可靠身份认证，不会放宽 Agent capability、资源 scope 或逐次写入确认。 实时监听中的关键词可能早于两秒声纹缓冲命中；此时运行时会保留该次命中并继续积累本地 PCM，达到模型最低窗口后自动完成声纹判断，不会把正常启动时序当作故障或停止监听。

本地语音模型默认采用国内优先下载：关键词模型来自 ModelScope，声纹模型来自固定哈希的 Hugging Face 国内镜像；也可选择自动回退或 GitHub/Hugging Face 全球源。下载请求不携带用户音频、声纹、资料或密钥，所有来源都必须通过文件大小与 SHA-256 校验。任务在应用内切换页面时继续运行并保留进度，前后端禁止重复任务，用户可显式取消；退出应用仍会终止下载。

桌面伙伴支持三种显示模式：互动模式保持置顶并接收点击；安静模式以约 80% 不透明度置顶但启用鼠标穿透；普通模式允许其他窗口覆盖且仍可点击。语音唤醒临时进入互动模式，会话结束恢复用户设置；默认 `Ctrl+Alt+Y` 全局显示/隐藏并在重新显示时进入互动模式，默认 `Ctrl+Alt+T` 在安静穿透与切换前的互动或普通窗口模式之间往返，两者都可更换或关闭且冲突时不会重复注册。系统托盘提供“显示并交谈 / 安静显示 / 隐藏 / 打开一隅 / 退出”兜底。开启语音唤醒后，关闭主窗口只隐藏界面，主进程和本地监听继续留在托盘；再次启动程序会唤出已有实例，不创建第二份。只有托盘“退出一隅”才彻底结束进程和麦克风监听。当前不注册 Windows 登录自启动，重启电脑后需要手动启动一次；程序完全退出时不存在无需进程即可工作的语音唤醒。
#### 语音连续会话

中文实时识别固定以 `zh` 为主语言、`en` 仅辅助识别英文术语，避免短句漂移到无关语种。唤醒后的免手会话使用服务端 VAD 自动判断一句话结束，当前参数偏向保留自然中文停顿；按键录音仍由用户按下开始、再次按下提交。

连续会话按 `sleeping / listening / committing / thinking / speaking / interrupted` 六种语义状态流转。模型生成或 TTS 朗读期间，用户重新开口会先暂停当前朗读；新话语确认后，中止旧轮次并把它作为下一问题发送，聊天窗中已经显示的旧内容不会被伪装成完整回复。若识别文本与正在播放的句子高度相似，则视为扬声器回声，不新建问题并恢复朗读。相同转写在短时间内重复提交也会被忽略。

TTS 在 Agent 确认最终文本后按完整语句分段合成，并保持原顺序连续播放；模型某一步尚可能转为 Tool Call 时，其流式文字只作为可撤销的界面预览，不进入朗读队列。若该步最终成为 Tool Call，界面清空临时文字，等待工具结果与模型整合后的最终回答；因此查询前草稿和查询后答案不会被重复朗读。开始实际播放时才进入 `speaking`，直到最后一句结束或用户停止。语音回答继续保持 2–4 句和纯口语文本，长内容完整显示在聊天窗、只朗读前段；暂停、停止、文字输入和语音打断都能随时接管。所有写入 Tool 仍经过原有权限确认，语音不能绕过安全边界。

后续只需补充端点确认、首个模型文本与首段音频的匿名耗时指标，用真实的 time-to-first-audio、误截断率和误打断率继续调校 VAD 与回声阈值。

依据：[ElevenLabs Realtime STT](https://elevenlabs.io/docs/api-reference/speech-to-text/v-1-speech-to-text-realtime)、[Conversation flow](https://elevenlabs.io/docs/eleven-agents/customization/conversation-flow)、[Voice agent latency optimization](https://elevenlabs.io/blog/voice-agent-latency-optimization)。这些资料用于改进一隅自己的 STT → Agent → TTS 链路，不代表要把内部 Agent 迁移到 ElevenLabs Agents。

新资料库默认关闭外部 AI；已有资料库若已经选择 DeepSeek，则兼容迁移为允许外部处理，避免升级后无提示中断现有能力。授权作品、章节和加密作品临时许可仍是更细一层限制，不能被隐私总开关放大。

### 4.2 第一阶段安全策略

- 模型不直接访问 Store、SQLite、Repository、文件、Shell 或 Tauri command。
- Tool 元数据声明输入 schema、capability、risk 和 scope；Runtime 在执行前统一校验。
- 写入确认卡标题、风险提示和按钮由本地代码生成；参数只以截断纯文本展示。
- 桌面伙伴窗口只接收裁剪后的显示快照，通过单独 capability 与主窗口通信。
- DeepSeek 和 ElevenLabs 继续由固定官方域名、固定路径和请求大小限制约束；长期 Key 只在 Rust/DPAPI 中使用。
- 审计只记录 Tool 名称、参数形状、权限结论、结果状态和耗时，不记录正文、搜索词、音频、Key 或 Tool Result。

### 4.3 全应用 Agent 功能契约

AI 伙伴不通过“读取整个数据库”掌握一隅，而是由每个页面声明自己的受控接入面。`AgentFeatureContract` 以 `Record<ViewId, ...>` 覆盖全部应用页面，并为每个页面列出：功能 ID、读取 scope、可跳转 destination 和必须注册的 Tool。新增 `ViewId` 时 TypeScript 会要求补充契约；Registry 启动时还会检查契约声明的 Tool 是否真实存在，避免界面已经上线、伙伴却无法介入。

当前数据流为：

```text
用户意图
  → Model Provider
  → Tool Registry（schema 校验）
  → Permission Engine（能力、风险、资源 scope）
  → Application Service
  → 现有 Store / Repository
```

读取权限细分为作品、章节、人物/地点/时间线、待办、日历事务、课表、朝问、日记、情绪、伙伴记忆、答案收藏、音乐信息与联网查询。旧版“日常规划”会兼容迁移到四个独立开关，新字段默认关闭；素材库不再属于 Agent 读取面。页面跳转等低风险展示行为默认允许。创建和修改仍需写入总开关；“平衡”模式自动执行新建待办、日历事务、完成待办和情绪记录，“始终询问”则确认所有写入，正文覆盖、课程与资料修改在两种模式下都继续确认。删除、密钥、任意文件、Shell 和系统控制仍不开放。

深层跳转统一使用 `app.open`，模型只可选择契约中的 destination，并可携带日期、周/月范围、记录 ID、筛选或设置分区。应用将其转换为持久化的导航意图，再由页面消费；模型不能直接调用任意 Store 方法或操纵 React State。例如“打开本月情绪回望”会打开首页、展开情绪回望并选择本月，“打开 9 月 20 日的日记”会进入对应日期。

已接入的按需读取包括日记搜索/正文、待办、日历事务、课表、当日及周/月情绪、朝问、人物/地点/时间线搜索与详情、伙伴记忆、答案收藏、当前音乐与公开网页搜索。`web.search` 只有在独立联网权限开启后可用，只把最长 200 字查询词交给 `www.bing.com` RSS 搜索端点，短暂失败时可回退到同样已授权的 `cn.bing.com`；仅允许这两个 Bing 主机之间最多三次跳转，不携带 Cookie、日记、上下文或本地文件。查询词在 Tool 真正联网前会再次经过 Egress Gateway，本地恢复出的真实姓名、电话等信息不会绕过脱敏与发送前审核。搜索返回标题、摘要和 URL，模型回答不强制展示来源。外部结果按不可信内容处理，不开放任意 URL 抓取。已有作品、章节及写入 Tool 继续复用同一 Registry；素材 Tool 已撤下。

联网诊断分为两层：权限页的“联网诊断”使用固定公开查询词直接测试 Rust/Bing 链路，不经过模型；正常 Agent 回合的最近 Tool 审计保存耗时与 `DNS / TLS / PROXY / CONNECT / TIMEOUT / HTTP_xxx / EMPTY_RSS` 等分类码。错误分类、设置页和诊断包均不保存实际搜索词、Cookie、正文或密钥。

联网检索通过独立 `WebSearchProvider` 边界实现，当前正式选项为腾讯云联网搜索和博查 Web Search，Bing RSS 只作为无密钥或服务故障时的可关闭应急降级。Provider 只在 Rust 后端访问固定 HTTPS 端点，密钥分别保存在 DPAPI 仓库中，不进入资料 JSON、Prompt、查询参数或审计正文。所有 Provider 统一返回标题、摘要、HTTPS URL 与实际来源标记；设置页诊断会显示实际命中的 Provider、结果数和耗时。`web.search`、权限检查、Egress Gateway 与 Agent Runtime 不感知具体搜索供应商。

## 5. 本轮实施范围

### 动态伙伴

- 多片段状态库与旧数据迁移。
- 新增情绪和姿势状态。
- 设置页按三组管理，可为每个状态继续添加或单独移除素材。伙伴立绘与 WebM 标记为独立技术资源，不出现在创作素材库；解除绑定后成为可清理文件，只有明确点击清理才从磁盘删除，仍在使用的资源不会被清理。
- 待机多片段自然轮换，其他状态按需随机选择。

### 隐私与安全

- 新增类型安全的 Trust Policy 与 Egress Gateway，统一判断模型出站、上下文/历史裁剪以及内容级脱敏。
- 在“隐私与安全”设置中增加外发控制、发送前确认模式和私密词典，并展示现有安全边界。
- DeepSeek 对话与“朝问”接入外部处理总开关。
- 对话上下文、最近历史和本地留存按设置裁剪。
- 用户输入、历史、上下文、Tool Result 和外部 TTS 文本统一经过本地规则；SECRET 在 Provider 调用前硬阻断。

- 建立覆盖全部 `ViewId` 的 Agent 功能契约、分类读取权限与受控深层导航；新增功能必须显式声明 Agent 支持面或保持为空，不能静默遗漏。

## 6. 中文隐私模型调研

第一阶段不打包本地模型。原因不是本地模型没有价值，而是中文专名、地址和证件格式对地区与语料高度敏感，必须先用一隅自己的简体中文样本评测误报、漏报、内存和冷启动。

候选顺序如下：

1. `lbsavf3t/rail-v2`：DistilBERT 级别、Apache-2.0，模型卡声明支持中文姓名、地址、手机号和大陆银行卡等标签，适合作为轻量 Windows 原型；它也明确建议与校验规则组合使用，但公开下载与中文基准证据仍少，不能直接视为生产结论。
2. `GLiNER2-PII` / `PII-Engineer-Chinese-NER-v1.0`：约 0.3B 参数，类别更丰富，中文模型卡给出了较高 F1 与 ONNX 路线；后者页面的许可证元数据与正文表述不一致，商业分发前必须先澄清许可证。
3. OpenAI Privacy Filter：1.5B 总参数、约 50M 激活参数、128K 上下文、Apache-2.0，适合作为高质量开放基线；官方也明确说明它不是匿名化或合规方案，表现会随语言和领域变化，因此不能仅凭总体 F1 推定简体中文效果。
4. `privacy-filter-tw`：针对繁体中文和台湾证件做过本地化，但模型卡披露困难负样本误报仍高，并依赖自定义解码器；可用于对比地区适配的重要性，不作为一隅的大陆简体中文默认模型。
5. `nym-pii-multilingual`：覆盖多语言且提供约 359 MB 的 int8 版本，可纳入交叉评测；模型卡同样建议对证件类弱项配合正则，当前没有足够的一隅场景中文证据。

参考：[OpenAI Privacy Filter](https://openai.com/index/introducing-openai-privacy-filter/)、[rail-v2](https://huggingface.co/lbsavf3t/rail-v2)、[PII Engineer Chinese NER](https://huggingface.co/pii-engineer/PII-Engineer-Chinese-NER-v1.0)、[privacy-filter-tw](https://huggingface.co/lianghsun/privacy-filter-tw)、[nym-pii-multilingual](https://huggingface.co/Wismut/nym-pii-multilingual)。

下一阶段若接本地模型，仍只作为检测器插件：规则与校验负责高精度格式，模型补足中文专名和语境；两者输出统一进入现有 Egress Gateway。模型不会获得 Provider、Tool 或数据库权限。

- 资料实体级 `INTERNAL / PRIVATE / SECRET` 标记；第一阶段先用私密词典承接显式标记，后续再接人物/地点编辑器。
- WebM 混合、骨骼动画、动作编辑器、Live2D SDK。
- 删除类 Tool、任意文件访问、Shell、Computer Use 或 MCP 对外暴露。

## 8. 验收标准

1. 旧版每状态一段 WebM 升级后仍正常播放。
2. `idle` 可添加至少三段并在播放结束后轮换，连续两次尽量不选同一段。
3. 新增表情或姿势缺失时安全回退待机；切换时不闪出默认人物。
4. TTS 全程保持 speaking，播放完成或用户停止后才恢复。
5. 关闭外部 AI 后，DeepSeek 对话与朝问在发出网络请求前被本地拒绝；本地 Mock 可继续使用。
6. 关闭上下文或历史共享后，对应内容不会进入 Provider 请求。
7. 关闭本地对话留存后，本轮回答可见但不追加到长期消息记录。
8. 写入仍必须经过 Tool Registry 和权限检查；低风险写入按用户选择的平衡策略执行，其余操作进入本地确认卡。桌面子窗口仍不能调用资料库命令。
9. 同一回合的同一私密词使用同一占位符；最终回复在本机恢复，Tool 参数恢复后才进入权限与业务层。
10. 检测到 SECRET 时 Provider 不被调用；普通隐私项按设置显示脱敏预览，取消后不发送。
11. 未授权日记、情绪或规划时相应 Tool 被 Permission Engine 拒绝；授权后可以按需查询真实本地数据。
12. `app.open` 只能打开契约列出的 destination，并能把本月情绪回望、指定日期日记/日历、待办筛选和具体资料转换为对应页面状态。
13. 新增应用页面若未补充 Agent 功能契约应在类型检查阶段暴露；契约中声明但未注册的 Tool 应在 Registry 创建时失败。

## 电脑能力层（2026-09-24）

AI 伙伴的电脑权限已作为 Agent Tool 的通用能力接入，而不是为“录屏介绍自己”写专用流程。调用链保持为：

~~~text
模型 → Agent Runtime → Tool Registry → 前端权限决策 → Rust 权限复核 → Windows/文件/进程/FFmpeg
~~~

现有能力包括应用和 HTTPS 链接打开、可见窗口列举/聚焦/移动/关闭、鼠标点击、Unicode 文本输入、受控快捷键、剪贴板、文件列举/搜索/文本读写/复制/移动/删除、结构化进程启动与停止、显式 PowerShell、系统通知、截图和录屏。录屏使用本机 FFmpeg，优先读取用户配置并自动探测常见 D 盘路径。 明确的“打开/访问 + 域名”请求由本地意图路由直接形成 `system.open` Tool Call，避免依赖模型随机决定；裸域名在 Rust 可信执行层补全为 HTTPS。成功回执只表示 ShellExecute 已把目标交给 Windows 默认处理程序，不宣称网页已完成加载。 执行意图层现也覆盖应用内页面跳转、音乐控制、全屏截图/开始录屏、剪贴板读取等参数确定的低歧义动作；其他创建、修改、文件、窗口与系统操作仍由模型按 Tool schema 规划。若明确执行请求第一次只得到文字而没有 Tool Call，Runtime 会丢弃该无效草稿并纠正重试一次，要求调用现有 Tool、询问缺失参数或明确真实能力缺口。所有路径仍经过原 Permission Engine、Rust 复核与审计。

安全边界：

- 电脑能力总开关默认关闭，旧资料库不会在升级后自动获得电脑权限。
- Tool 必须声明 capability、风险级别和目标参数；Tauri 主进程会再次执行同一能力检查，不能只依赖前端。
- 文件访问使用绝对路径、规范化路径和目录授权；敏感凭据目录需要明确确认；文本读取与写入有大小上限；目录删除不递归。
- 程序使用参数数组直接启动，不把普通程序调用拼接进 Shell。PowerShell、文件删除、进程停止以及具有破坏性的窗口/移动操作始终逐次确认。
- 伙伴只能停止自己启动并登记的进程，不能按任意 PID 终止系统进程。
- Agent 审计记录 Tool、目标、权限原因、是否逐次确认、结果与耗时；参数中的内容、密钥和 Token 会脱敏。
- 托盘与全局快捷键提供紧急停止，统一中止伙伴启动的录屏和后台进程。
- “受信任工作站”只自动放行可见桌面交互、截图录屏、剪贴板和通知；目录、程序与 Shell 仍需规则或逐次确认。

后台事务提醒复用现有日历与待办数据。程序在托盘中运行时，每 30 秒检查一次到期窗口并发出 Windows 通知；程序真正退出后不承诺继续提醒。后续新增电脑功能必须先注册为 Tool，声明 capability、目标、风险和审计语义，不能从模型直接调用任意 Tauri command。
电脑能力的设置界面复用“权限与调用记录”的权限行、策略行和折叠授权卡，不建立独立视觉体系。默认只展示总开关、默认模式和提醒；录屏安全与长期规则按需展开。后续增加 Agent 或电脑能力时，优先组合现有设置组件、字号和间距契约，避免每项功能形成新的面板风格。

## 共享素材自动备份（2026-10-03）

自动备份默认间隔 3 个本地日、保留最近 3 份，可在数据管理调整；旧默认 14 份升级为 3 份，自定义数量与关闭状态保留。每份 .yiyu-snapshot 含资料和完整的素材引用清单，assets（包括伙伴 WebM）、audio 与加密 vault 按 SHA-256 存入同目录的“共享素材”；未变化的文件只占一份，不形成依赖前一个快照的增量链。内容发生变化会保存新版本，旧版本仍被任何保留快照引用时不会回收。

自动快照从备份记录中预览、恢复。迁移需复制整个备份目录，不能只携带一个快照；单文件携带使用“立即完整备份”的 .yiyu-backup，原完整备份继续兼容，恢复前仍创建完整安全备份。首次共享备份仍需复制所有素材；记录中的 MB 是快照本体，不包含共享目录体积。

恢复先校验资料、清单、全部素材大小及 SHA-256，缺失/损坏素材不替换当前资料；目录交换和数据库保存失败成组回滚。清理只发生在新快照验证完成后，手动完整备份不参与自动保留策略；全部剩余快照引用清单校验成功后才回收无引用 hash 文件，损坏清单会停止清理。后台文件任务串行，流式处理大文件，列表只读取 manifest 与大小；新路径入口仅 main 窗口可调用，且约束于所选备份目录，不扩大伙伴窗口能力，不备份 API Key 或声纹 embedding。

## 桌宠当前实现与动态美术路线（更新2026-10-05）

现有桌面窗口实际使用 Tauri 2。Character入口分别选择WebM Renderer与独立Pixel Pet Renderer，不把桌宠逻辑嵌入视频播放器；默认保留原模式。设置 → 桌面伙伴 → 桌宠与造型，可切换精细插画、像素半身、Q版，支持左右扒边、底部趴边和自然半身；选择随资料库保存并同步桌面，原WebM素材、校准与调度不变。旧库/非法造型值回退Q版，桌宠仍默认关闭。当前操作见[桌面伙伴使用说明](../桌面伙伴使用说明.md)，本节保留母图/动画与后续各项已批准实现的技术依据。

三套为用户已批准的重新设计静态美术，不直接缩小原参考立绘。原 PNG 不改动。针对首版硬切分层独立平移导致的偶发接缝，Canvas 现保留完整母图，以连续有界逐扫描线映射驱动微呼吸、头动与延迟发摆；手部高度平滑固定、右侧边界不动，不需要补绘隐藏颈部或衣袖。眼睛保留原图眼白、睫毛、高光与颜色，原虹膜在固定眼部范围内真实平移，三套分别按眼睛大小约束幅度；露出的眼白采样自原眼白，采用双线性插值与椭圆 clamp，不再把虹膜拉伸作为眼动。中性视线恢复原图所有像素；眨眼压缩原眼纹理、插值邻近肤色并沿用原睫毛颜色，不重新画通用眼形。没有预渲染帧、Live2D 或复杂骨骼，大动作及探头/睡眠姿态仍不支持；DEC-055已补独立底部趴边母图，眼部插值自然度关联 R-036，需实际体验。

逻辑视口 192×240，保持源图比例；按抓握边缘而非 PNG 透明留白贴右侧，超边指尖/发带有意裁切。左侧使用同一母图的水平镜像，发饰换边；输入鼠标坐标与输出画布一起镜像，保持原眼位校准和正确追踪方向。画布 backing 为 576×720，三套都在三倍内部精度准备以保留眼部细节；像素半身与 Q 版禁整图平滑，精细版使用平滑，保留原色和 alpha，不做整图透明硬阈值处理；Windows 默认显示尺寸仍对应 100% 下 192×240 物理像素，多屏/分数 DPI 沿用整数物理倍率。隐藏/卸载暂停绘制；只有模式启用或预览展开才准备素材，缓存按造型＋侧边/底部/自然半身分组，最多九份按需准备。切换时保留旧画面至新素材准备好，解码失败保留已绘制的上一画面，首次没有画面时明确回退代码原型。

Tauri cursorPosition 的全屏物理坐标经 innerPosition、scaleFactor 与 DOM 矩形转换到逻辑视口，ref 进入 animator；按每套实际眼部中心计算视线，连续 clamp/easing。原生拖动仍用 5 CSS 像素阈值，拖动不打开聊天，单击打开对话；quiet 穿透必须先开启互动。退出模式恢复原窗口几何，手动 WebM 预览临时使用原分支。未扩大插件窗口权限或运行时网络/资料访问；DEC-055仅新增companion可用的当前左键布尔读取供主动拖动松手判断，鼠标位置/按键历史不记录或外发。

设置预览只在展开时挂载，可切实际大小/放大；浏览器 `?pixel-pet-preview=1` 支持三套并排与放大比较，`&style=detailed|pixel|chibi` 选择初始样式。浏览器只追踪页面鼠标，桌面追踪屏幕鼠标；`&side=left-edge|right-edge|bottom-edge` 可指定预览初始方向。两端都支持悬停安定和约六秒静止后的缓慢回正，点击预览身体轻眨眼，轻点头部短暂眯眼。

主要模块：

- `src/modules/companion/pixel-pet/`：Renderer、动画、坐标、拖动、窗口布局与设置。
- `pixel-pet/art/`：已批准静态资源、每套锚点、完整母图准备、连续变形与局部原眼采样。
- `DesktopWebMRenderer.tsx`：原视频/立绘分支保持不变。
- `CompanionPetStyle`：仅三种允许值，资料库兼容补齐后进入桌面快照。

经 DEC-054 确认，PixelPetPose 的 right-edge / left-edge 已同时实现；后经DEC-055实现bottom-edge，DEC-056实现float及独立视觉休息状态；peek和独立sleep睡姿仍仅为扩展接口。设置方向随资料库保存，缺失/非法值回退右侧，切换会停靠当前屏幕对应边缘并保留垂直位置；退出桌宠恢复本设备独立保存的 WebM 几何。悬停约300ms后以6逻辑像素容差稳定关注，不追随微抖；离开且无明显移动约六秒，视线以较慢缓动回正，重新移动恢复关注。点击轻眨眼不重启正在进行的眨眼，短时间重复点击不叠加，拖动不触发回应或聊天，键盘激活保留同样行为。

主窗口固定注册 `Ctrl+Alt+Q` 切换已保存桌宠/原 WebM 渲染模式，并显现角色；没有 WebM 素材时回到已有原角色回退，不创建或删除素材。长按只响应一次，释放后可再次切换。与既有显隐/安静/启用的紧急停止组合冲突时不抢占，注册失败也不会注销其他绑定；设置显示原因。快捷键生命周期串行清理，只使用现有主窗口 global-shortcut 权限。安静模式仍穿透，点击/拖动仅在非穿透模式可用。连续绘制修正的 25 项定向与眼动精修的 19 项定向、UI 门禁及浏览器实绘通过；三套中性输出与源图同尺寸绘制逐像素一致，极值检查未见内部透明空缝，闭眼检测区无蓝色残留。实际 Windows 外观、追鼠标手感、DPI 和眨眼仍待用户自然复验。正式版本与 M12 状态不变。


### 底部趴边与位置/对话联动（DEC-055，2026-10-04）

三套各新增一张透明静态底部母图：水平前臂与双手，不旋转侧边姿势、不替换原三张PNG，仍以192×240逻辑视口与代码实时动画绘制。按各自眼位/手臂水平锚点校准，保持比例；底部抓握行的横纵位移都固定。设置方向增加“底部趴边”，开发预览可模拟待机、倾听、思考、回应与失败，不发AI请求。

拖动近左右/底部工作区边缘，在松手后以24 CSS逻辑像素等价阈值吸附，自动同步方向；角点同距离时优先当前姿势。中间保留自由位置。方向显式切换时，侧边保留纵向位置、底部保留横向位置。只在主动拖动期间约80ms读取当前左键布尔状态，native startDragging成功不被当作松手；pointerup备用、查询失败与卸载清理、120秒保险超时。原WebM只共用位置管理，不改变视频调度。

设备 localStorage 的版本化记录分别保存Pixel/WebM的物理位置、尺寸、工作区与DPI，不随资料库/备份迁移，不保存鼠标轨迹。重启按模式恢复，显示器变化映射相对位置并校正可见范围；坏记录、存储拒绝或容量不足不阻断应用，仅用会话内位置。

倾听时稳定入场视线并降低微动，思考时轻微向下/侧移，回应中保留轻动态，回应结束轻眨眼；复用既有action与Agent状态，不切换表情图、不改变语音状态机。原生多屏吸边、模式切换与新增母图相似度仍需自然体验。


### 自然放置、休息与右键菜单（DEC-056，2026-10-04）

三套各新增 `*-free-v1.png` 透明静态母图，双手轻合在身前，显示自然半身而非悬空扒边；原侧边/底部母图不改。运行时沿用原眼纹理连续平移和眨眼，未生成动画帧。经DEC-057稳定性修正，自然半身闲时固定身体轮廓，不再持续逐行晃动；拖动和有限轻倾仅用完整母纹理的平滑整图变换。拖动时暂用自然半身，读取已有原生移动事件产生小幅惯性随动；减少动态效果时不随动。松手近边恢复对应扒边，远边保持自然姿态，姿态由本机几何派生，不新增资料字段或备份格式。右键可显式选自然放置（移动到当前工作区中央）或三种扒边；同方向仍可重新停靠。

约90秒没有角色悬停/点击/拖动/菜单互动，且不在倾听/思考/回应/失败状态时缓慢轻闭眼、减弱微动；互动后快速醒来。只是内存视觉休息，不关闭关键词唤醒、麦克风、TTS、任务或进程，不读取整机空闲或保存活动记录。隐藏暂停绘制，重新显现恢复清醒。原随机眨眼与点击回应保留。

右键菜单在原桌宠窗口内显示，不扩窗或增加原生菜单权限：切换三套造型、摆放姿态、打开设置、暂时隐藏。支持键盘上下/Tab/Home/End/Escape；外部点击/失焦、隐藏/模式切换关闭，点击角色只关闭已打开菜单，不顺带触发聊天/拖动。造型/方向/设置/显隐仅以有限枚举转发主窗口，主窗口按最新模式确认后调用既有Store动作，无任意命令或资料读取。安静穿透仍不接收右键，先用既有安静快捷键恢复互动；隐藏后可用显隐快捷键、托盘或已配置语音唤醒恢复。

设置动态预览新增自然半身比较，调试页 `?pixel-pet-preview=1&pose=float` 可直接查看自然姿态，并可切换休息预览/唤醒预览；浏览器预览不会触发语音或AI。新母图外观与实际Windows拖动/休息手感仍按自然体验收集反馈。

### 稳定半身与轻互动（DEC-057，2026-10-04）

自然半身的眼动/眨眼独立于稳定身体，边缘姿态仍有缩小的微动；动画器输出独立帧快照，motion只调呈现参数，不污染下一帧缓动。轻点头部约1秒眯眼回应，按三套造型和姿态校准命中区域、左右同步镜像；1800ms防连击。身体点击与键盘仍打开聊天，拖动不误触，右键/双击/安静穿透与Ctrl+Alt+Q保留，预览也支持头部回应。

无鼠标关注、对话、拖动、菜单或休息时，以30–55秒间隔交替短暂轻倾和视线小动作，动作约3秒，收回平滑而非切图片；不会重置90秒视觉休息计时。减少动态效果时关闭身体随动和空闲小动作，保留眼动/眨眼/摸头眯眼，不增加设置项、存储记录或权限。浏览器中性和身体时序验证不替代实际WebView2/DPI下的稳定感体验。

### 简短任务反馈与唯一伙伴名字（DEC-058，2026-10-04）

角色显现且非安静穿透时，旁边的244×64透明小窗按已有任务真实状态显示“等待开始 / 正在准备 / 正在执行 / 等你确认 / 已经完成 / 遇到问题 / 已停止”和完成步数。优先待确认/执行任务，不让旧完成或失败遮盖新进展；普通提示约6.5秒自动收起，悬停可保留便于点击，等待确认保持到处理或主动收起。收起不停止任务，隐藏/quiet不弹窗，启动不重播历史完成。

点击提示只打开原桌面对话中的任务详情并展开步骤，不必打开主界面、不清空草稿；暂停、继续、停止和“允许此步并继续”沿用已有TaskActionRegistry及逐次权限。新小窗没有通用event、资料、素材或语音权限：main专用命令发布状态枚举/任务ID/计数，子窗通过标签守卫Channel接收，原生仅转交当前任务的查看/收起/悬停请求；不传标题、目标、参数、错误原文或产物路径。贴近当前工作区放置，超边clamp、移动120ms防抖；normal不强制置顶。

设置“伙伴名字”是唯一入口，默认“小鱼”；失焦/回车保存，AI受控自我身份、桌面称呼、任务语音文案和唤醒名称同步。旧默认“小隅”配有效旧唤醒词时采用旧唤醒名，自定义名字保留；voice.wakeWord只为旧备份/schema兼容保留镜像。改名不删除既有对话、声纹、API Key或WebM。当前本地关键词模型仅支持2～6个汉字；其他名字可用于显示/AI，但唤醒明确关闭，不保留秘密旧别名。语音服务、模型、声纹及外发开关仍须按原流程就绪，不因改名自动启用。

改名重新启动本地监听时，native调用串行、每个capture有租约；迟到旧PCM/麦克风和旧云端回调不得停止或污染新监听。罕见汉字/口音与真实模型身份输出仍需本机体验，自动结果不代替实际唤醒和多屏验收。新增隐藏WebView的资源代价关联R037，未宣称零成本。

### 场景对白与语音字幕（DEC-059、DEC-065，2026-10-05）

桌宠点击默认打开300×210轻量对白，WebM普通点击保留380×480完整聊天；名字唤醒打开轻量语音框，桌宠280×160、WebM320×160。桌宠银蓝小卡、像素造型方角，WebM暖白轻纸，长对白纯文字预览可展开，完整聊天保留原文/Markdown、草稿、流式内容、录音链与任务，不新建另一套会话。

语音只显示此刻实际播放的TTS句子，不用尚未朗读的模型文字替代；末句结束约6秒后回到待听提示，鼠标/焦点阅读延长保留，新一轮倾听立即退旧句，暂停朗读仍保留当前句。主动文字对白不自动消失；状态只在真实倾听/朗读时说明“我在听/正在说”，未开始的语音展示可正常结束。展开聚焦输入、中文选字Enter不发送，Shift+Enter换行；完整历史在底部跟随流式，往上阅读不抢滚动，提供回最新回复按钮。

定位沿用前端Tauri窗口API，不改native权限；按角色实际外窗矩形选择左/右/上/下并尽量避免覆盖整个人物，底部优先上方，以目标屏幕物理尺寸处理DPI、负坐标和工作区限幅，移动后保留对应模式尺寸。极小工作区无足够空间时优先可见并最小化重叠，不承诺任意屏幕无重叠。授权/隐私/任务确认仍强制完整形式、明确点击，不因缩略、计时或收起自动允许。

权限、发送前隐私预览和待确认任务强制使用完整界面与原明确按钮，不自动同意；语音结束不自动隐藏待确认项。布局串行调整，不移动角色，底部趴边优先在上方，左右/工作区/DPI校正；原生多屏仍需实际体验。

### 仅本机实时心率（DEC-059、DEC-062、DEC-064）

入口为“设置 → 桌面伙伴 → 实时心率”。首次默认关闭，开启广播并扫描选择手表：佳明265长按UP → 健康与保健 → 腕式心率 → 广播心率 → START（菜单随固件可能不同）。首次或升级后成功连接一次才记住设备，之后启用即可自动查找它；可显式开启“启动时自动连接”。广播未开/离线时每轮最多3次，首次后15/45秒退避，不无限扫描；停止连接取消本次自动尝试，忘记设备清除本机偏好并停止。手表广播仍需开启，软件不能替手表开启广播；结束时手表STOP。相关菜单见[佳明官方手册](https://www8.garmin.com/manuals/webhelp/GUID-F41EAFB3-6CC9-42DE-9C6C-9E358DBB0671/EN-US/GUID-D8D363C2-0690-48D4-95E2-A3557E7D53C2.html)。

原生Windows后台订阅标准BLE心率服务0x180D/通知0x2A37，仅提取bpm；8秒扫描、每项异步操作15秒期限、取消和代次隔离。10秒无新数据、无接触或无效通知时不继续显示上一条数值。主窗口显示设备列表与读数，角色只接收最小状态/读数，隐藏时不显示；安静模式仍显示轻量读数并保持鼠标穿透。

仅main标签可调用设备命令，原地址不序列化，设备名字/标记不传角色。固定标记由广播地址加应用前缀哈希派生，不是不可回推匿名化或身份认证；只匹配当前扫描列表，不替换同名设备。标识变更时需重新选择。名称/标记/自动开关仅保存在本机WebView偏好，不入LibraryData、资料备份、AI、审计或网络；读数无持久历史。设置保留环形读数；角色呈现改为两条独立路径（DEC-064）：WebM轻量心形/数值/bpm旁注，不加角色反应；桌宠按画风的小心形与常驻数字，左右镜像定位、底部趴边置上方、自然半身左下角，不挡拖动。装饰脉动随当前bpm平滑调节、舒适频率限幅，无数据静止、减少动态效果关闭，既非逐次真实心跳也非ECG。

桌宠先建立约8秒的临时基线；同方向变化至少max(12bpm,基线18%)并持续约12秒，才偶尔看向标记约1.8秒后回归，至少间隔2分钟。仅虹膜视线，不增加身体抖动；按实际DOM标记中心转换画布坐标并处理镜像。鼠标关注、摸头、拖动、菜单、交谈、休息和减少动态效果优先，打断即取消且不补演；数据停止/过期/不可见清空临时状态。此调参不是医学或情绪判断，不播报警、不进AI、不存历史，仅会话内标量；安静模式可回应但不改变穿透。广播本身并非加密私密连接且增加耗电，仅需要时开启（[佳明广播说明](https://support.garmin.com/nl-NL/?faq=Zj1947s6pqAHzBCAhLhrC9)）；读数非健康诊断。模拟与编译不代表265真实重连、地址稳定性或驱动已验收。

### 一隅签（DEC-059、DEC-061、DEC-063）

左侧“一隅签”先呈现共用木签台：今日签48支保留原编号和文案，恋爱签24支、前程签24支使用独立原创签库，共96支。素纸青枝、樱色红绳、墨竹淡金区分三筒，不另设模式页。选择一筒后轻摇、出签、展纸；恋爱签以未确定关系的相处为主，含相遇/心意/行动，前程签兼顾工作、学习和创作，含进展/阻碍/时机。吉凶只是文学提醒，不推测他人心意、不预测现实。支持深色、窄窗口和减少动态效果。

每筒每天各抽一次，相互不覆盖；点已抽的筒直接看原签，签纸下可回签台选择另一筒，无重播按钮。选筒不消耗次数，点击轻摇时保存该筒日期/稳定号；中途关闭不会重新抽，动画期间锁定切换，跨本地午夜取消旧动画。每类仅保留最近一次结果，不建立历史、收藏、许愿或签到。旧`fortune.today`保留，新增可选`love`/`future`，复用资料与完整/共享素材备份路径；新版可读旧备份，旧程序再次保存可能丢弃新主题字段，跨机请使用新版。无AI、网络或心事输入。设置→功能与导航可关闭整个入口，不删除三类结果。

签台增加“为自己求签 / 替别人抽”轻量切换。默认自己，客签共用三种原创签库、摇筒/出签/展纸，签纸明确标记“客签”；不写资料、不占用或覆盖自己的每日次数，不输入来客姓名/心事，不进入备份或AI。临时结果仅在当前仪式中，可再请一位来客；回签台、切对象、离开页面或跨日清空。动画中禁止换对象/主题，减少动态效果直接展纸。签页单独采用工具栏＋剩余空间两行网格，背景铺满内容区，长签依然滚动，不覆盖侧栏和标题栏。
