# 新设备沿用已有配置

这是功能分支预览，不需要把 API Key 粘贴到聊天里，也不会自动复制浏览器账号或系统权限。

## 怎么用

1. 更新两端应用和中枢代码；不要重新初始化中枢或清空手机资料。现有数据库会增加独立的交接表。
2. 新设备配对时保留「连接后申请沿用对话模型配置」，或在连接设置的「沿用已有配置」中选择对话模型/语音。可选择只交接一次或跟随以后更新。
3. 新设备显示一组校验码。在已有设备打开同一设置，输入这组码；在随后出现的系统原生确认窗核对同一校验码与服务范围，再批准一次。不是网页内自行勾选的许可。请求十分钟有效，Android原生确认窗45秒无操作会取消。
4. 两端在线时自动交接；可点「刷新交接状态」。已有设备离线时需等它回来，不需要再次手填 Key。
5. 以后想独立调整，点「停止跟随，保留当前配置」。手动保存本机 Key 也会阻断原交接继续覆盖；重新跟随需发起新请求并批准。已有设备也可停止提供更新。

当前兼容：官方 DeepSeek 的 `deepseek-chat` / `deepseek-reasoner`，以及 ElevenLabs 的声音ID、`scribe_v1/v2` 与 multilingual v2 / flash v2.5 / turbo v2.5。手机没有的自定义端点、搜索API、生图、设备唤醒参数不强行迁移。网页预览不接收真实密钥。

## 隐私和失败处理

- 使用独立的原生加密通道，不是普通资料同步；Key不进入邀请、聊天、模型上下文或普通资料备份。Windows 用 DPAPI，Android 用 Keystore 保护的 AES 密文重新保存。
- 接收设备专属 P-256 密钥协商、HKDF-SHA256 与 AES-256-GCM；请求/密文另由资料组HMAC认证。中枢没有解密密钥，不能独自替换目标公钥；批准时仍必须核对新设备校验码。已持组密钥的恶意设备或本机恶意代码不在这项防护保证内。
- 原生端另保存目标/范围许可，普通密钥写入接口不能伪造该许可；未批准或撤销后拒绝封装。单次复制固定为批准时的密钥快照，不因重试获得后来轮换的Key。导入配置会结束手机当前语音会话，需本人重新开启。
- Android 为兼容 API26，将 ECDH 私钥用 Keystore AES 包封，不宣称所有机型都具备硬件不可导出ECDH。实现参考 [RustCrypto P-256](https://docs.rs/p256/0.13.2/p256/) 与 [Android KeyAgreement](https://developer.android.com/reference/javax/crypto/KeyAgreement)。
- 只更新所选服务，不开启麦克风/摄像头或复制浏览器登录。断网/校验失败保留现有配置，成功保存后才确认；手动修改优先于后续跟随。
- 中枢每目标只留一条通道、最多32条、单包有界；成功确认即清当前包，停止/拒绝/撤销后清通道。已批准通道双方都离线七天后过期，重发需本人重新批准。旧密文可能留在中枢备份，不称安全擦除。
- 共用 Key 消耗同一账户额度。撤销同步设备不能使已收到的服务商 Key 失效；设备丢失请在服务商轮换 Key。
- 中枢没有升级时，资料仍能同步，配置交接单独提示未完成。无网络时停止跟随也先在本机生效，联网再清中枢通道。

自动验证只用虚构凭证/隔离中枢；原生真机和实际跨网仍需体验。更新安装包与状态见[当前候选](../.agent/PROJECT_STATE.md)。
