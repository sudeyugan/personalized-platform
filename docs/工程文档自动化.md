# 工程文档自动化

## 目标

把版本、里程碑和验收状态从“依靠 Agent 记忆”改为机器校验。产品需求、用户反馈原文和架构原因仍由人维护；机械状态由脚本生成。

## 唯一机器状态源

`.agent/project-status.json` 保存：

- 应用版本、当前/下一里程碑和固定状态枚举。
- 自动门禁与人工验收状态。
- 安装包相对路径和 SHA-256。
- 各里程碑的状态和简短证据。

允许的阶段状态：`not_started`、`in_progress`、`auto_verified`、`delivered_pending_manual`、`verified`、`blocked`、`cancelled`。

## 自动生成区块

以下文件含 `<!-- generated:*:start/end -->` 区块，禁止手工维护区块内部：

- 根 `README.md`
- `docs/README.md`
- `docs/product/README.md`
- `.agent/PROJECT_STATE.md`
- `.agent/ROADMAP.md`
- `docs/product/04-开发路线图.md`
- `docs/product/05-AI编程交接指南.md`

运行 `pnpm docs:sync` 后，这些区块会从状态源统一更新；区块外的解释、风险、偏差和用户反馈不会被覆盖。

## 检查命令

`pnpm docs:check` 用于源码和 CI，检查：

- 根、桌面、Tauri 和 Cargo 版本是否一致。
- 状态枚举、当前/下一里程碑和自动/人工验收组合是否合法。
- 所有生成区块是否与状态源一致。
- 当前版本是否存在体验反馈章节。
- 已交付版本是否记录正确格式的安装包路径和 SHA-256。
- 维护范围内的 Markdown 本地链接是否有效。

`pnpm release:check` 额外要求本机安装包实际存在且哈希完全一致。CI 不要求仓库提交构建产物，因此使用前者。

`pnpm docs:test` 使用 Node 内置测试验证状态组合约束和生成区块替换规则，并在 CI 中先于一致性检查运行。

## 标准流程

```powershell
# 日常定向内循环：必须给出相关测试文件
pnpm verify:quick -- src/modules/writing/EditorToolbar.test.tsx

# 一批纯前端/UI 代码准备交付，不生成安装包
pnpm verify:ui

# 一批跨层或高风险代码准备交付，不生成安装包
pnpm verify:full

# 用户明确需要本地可安装候选时，仅打包，不改变正式发布状态
pnpm release:build

# 里程碑正式发布
pnpm release:prepare 0.2.0 M3 M4 "完成人物、地点、事件与章节双向关联"
```

`verify:ui` 只执行 typecheck、lint 和 Web build，不自动运行测试；`verify:full` 才执行前端全量与 Rust 测试。普通低风险任务可以不运行二者，直接交给用户体验，但必须如实标注“未自动验证”。它们都不生成 NSIS、不修改版本状态、不刷新哈希。

`release:build` 只生成本机 Tauri/NSIS 候选，不登记为正式发布。使用者必须先完成与风险匹配的验证；范围不清楚或涉及 Rust、存储、安全、权限时使用 `verify:full`。

`release:prepare`、`release:patch` 和 `release:patch:ui` 仅用于真正交付安装包，仍负责验证、Tauri/NSIS、状态同步和哈希。正式补丁必须显式提供比当前版本更高、但 major/minor 相同的补丁版本和摘要，例如：

```powershell
pnpm release:patch:ui -- 2.0.1 "修复设置页布局"
pnpm release:patch -- 2.0.2 "修复备份恢复边界"
```

不要在正式发布前机械预跑同一套全量命令。脚本拒绝覆盖当前版本，确保同一公开版本不会对应多个不同二进制。

普通任务不要求同步整套文档，也不要求默认运行自动测试。只有版本、里程碑、计划、架构、风险、用户决策或验收状态实际变化时，才更新相应文件。CI 仅在 Pull Request、`v*` 发布标签或手动触发时执行全量检查，不再覆盖每次普通 push。历史门禁流水已归档，不参与日常上下文加载。

## 人工维护边界

脚本不会自动改写：

- 产品需求和用户反馈原文。
- 架构选择的原因及 ADR。
- 实现偏差、风险影响和缓解策略。
- 版本实现摘要之外的体验结论。

这些内容仍由 Agent 或开发者撰写，但 `AGENTS.md` 和质量门禁要求在里程碑结束时同步。
